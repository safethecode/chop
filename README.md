# Chop

원하는 칸에 터미널을 추가하고 나눠 쓰는 macOS 네이티브 앱입니다.
Swift와 AppKit, [libghostty](https://github.com/ghostty-org/ghostty)의 Metal 터미널 엔진을 사용합니다.
[cmux](https://github.com/manaflow-ai/cmux)의 작업 공간과 알림 기능을 참고하되, Chop은 중앙 `+`와 레이아웃 중심의 조작 방식을 사용합니다.

처음 열면 2×2의 4칸을 배치하고 왼쪽 위 **터미널 1을 바로 실행**합니다.
터미널 2·3·4는 빈 칸 중앙의 `+`를 눌렀을 때 열립니다. 입력·한글·선택·스크롤·복사·붙여넣기를 사용할 수 있습니다.
상단에서 1칸·좌우·상하·4칸 프리셋을 고르거나, 레이아웃 편집 중 각 실행 칸의 중앙 `+`로 오른쪽/아래에 터미널을 추가합니다.
분할 경계를 드래그해 크기를 조절해도 기존 셸은 유지됩니다. 실행 중인 터미널이 사라지는 프리셋 축소는 비활성화됩니다.
셸이 종료되면 빈 칸으로 돌아갑니다. 빈 칸의 닫기를 누르면 인접 칸과 합쳐지며, 마지막 빈 칸은 유지합니다. 실행 중인 작업을 닫거나 창·앱을 종료할 때는 확인합니다.
방향키로 칸 사이를 이동하고 한 칸을 확대해도 다른 셸의 작업은 계속됩니다. 이름 변경과 빈 칸 제거를 지원합니다.
레이아웃·분할 비율·칸 이름·작업 경로·열림 상태·선택한 칸을 자동 저장하고 다음 실행에서 복원합니다.

| 동작 | 단축키 |
|---|---|
| 현재 칸에서 터미널 열기 / 닫기 (빈 칸이면 제거) | `⌘T` / `⌘W` |
| 오른쪽 / 아래로 나누기 | `⌘D` / `⌘⇧D` |
| 레이아웃 편집 | `⌘⇧L` |
| 인접 칸으로 이동 | `⌘⌥방향키` |
| 현재 칸 확대 / 전체 레이아웃 복귀 | `⌘⇧Enter` |
| 현재 칸 이름 변경 | `⌘⇧R` |
| 스크롤백 맨 위 / 맨 아래 | `⌘↑` / `⌘↓` |
| 한 페이지 위 / 아래 | `⇧Page Up` / `⇧Page Down` |
| 윈도우 닫기 | `⌘⇧W` |

칸은 최소 280×180pt이며 화면에 들어가는 범위에서 최대 16개까지 자유 분할할 수 있습니다.
필요하면 창이 최소 크기까지 늘어나며, 더 들어가지 않는 방향의 추가 메뉴는 비활성화됩니다.

## 작업 공간 복원

`~/Library/Application Support/Chop/session.json`에 로컬 저장합니다. 변경은 짧게 모아 저장하고 앱 종료 직전에 한 번 더 저장합니다.
앱을 다시 열면 실행 중이던 칸에는 **새 셸**을 열고 나머지 칸은 비워 둡니다. 실행 중이던 칸이 하나도 없으면 첫 칸을 엽니다.
이전 버전의 단일 빈 칸 저장은 이름·경로를 유지하면서 기본 4칸으로 전환합니다. 이름·경로·분할 비율·포커스를 복원하며,
이전 프로세스, 셸 변수, 입력 기록, 화면 내용이나 실행 명령은 저장하지 않습니다.
셸 자체의 시작 설정과 히스토리 처리는 사용자의 셸 설정을 따릅니다.

- 작업 폴더가 없거나 열 수 없으면 알림 후 홈 폴더로 대체합니다.
- 손상·지원하지 않는 형식의 파일은 `session-unreadable-<UUID>.json`으로 보존하고 기본 4칸(1번 실행, 나머지 `+`)으로 시작합니다.
- 저장 실패는 알림과 터미널 메뉴의 ‘레이아웃 다시 저장’으로 처리합니다. 저장하지 못한 채 종료하려면 별도 확인을 거칩니다.
- 창을 직접 닫으면 그 안의 터미널을 닫습니다. 앱 종료는 마지막으로 열려 있던 칸의 상태를 저장한 뒤 셸을 종료합니다.

현재 v0.1 범위는 구현했습니다. 알림·Git 브랜치 표시·CLI와 브라우저/에이전트 연동은 후속 범위입니다.

## 개발 환경

- macOS 14 이상
- Xcode 16 이상 / Swift 6 이상
- Xcode Command Line Tools (`xcode-select -p`로 선택된 개발 도구 확인)

첫 빌드는 공식 Ghostty 소스와 Zig 0.14.1을 내려받아 libghostty를 컴파일합니다. 이후에는 캐시를 재사용합니다.
Metal 도구가 없으면 Xcode의 공식 MetalToolchain 구성 요소도 준비합니다.
엔진 버전과 빌드 환경 안내는 [Dependencies/README.md](Dependencies/README.md)에 있습니다.
먼저 `./scripts/prepare-ghostty.sh`를 실행하면 Xcode에서 `Package.swift`를 열어 소스를 편집할 수 있습니다.

## 실행

```sh
./scripts/run.sh
```

디버그 빌드 후 `build/debug/Chop.app`을 만들어 실행합니다.
이미 실행 중이면 기존 앱을 활성화하므로, 변경한 코드를 실행하려면 먼저 앱을 종료합니다.

릴리스 빌드와 실행:

```sh
./scripts/run.sh release
```

앱 번들만 만들려면:

```sh
./scripts/build-app.sh release
```

`build/release/Chop.app`이 생성됩니다. 개발용 임시 서명을 사용하며, 외부 배포용 Developer ID 서명과 공증은 포함하지 않습니다.

## 검증

```sh
./scripts/check.sh
```

Swift 포맷, 셸 스크립트 문법, 앱 메타데이터, 릴리스 빌드와 앱 서명을 검증한 뒤 `swift test`를 실행합니다.
통합 테스트는 실제 셸의 명령 출력·경로·분할 후 상태 유지·숨긴 셸의 작업 완료·종료 후 새 셸 복원을 확인합니다.
모델 테스트는 공간 이동·분할과 병합·저장 형식 검증·손상 파일 보존·쓰기 실패를 확인합니다.
테스트 셸은 `/bin/zsh`로 고정하며, 분리된 클립보드와 NSTextInputClient의 한글 조합·확정도 검증합니다.
GitHub Actions도 같은 명령을 실행합니다. 스크롤백은 실제 표시 영역의 상단/하단 및 페이지 이동을 검사합니다. 창·메뉴·실제 키보드 및 입력기 동작은 앱에서도 확인합니다.
실제 키보드 스크롤과 마우스 선택은 확인했으며, 마우스 휠은 자동화 도구 오류로 실기 검증하지 못했습니다. macOS 14 실기기와 전체 VoiceOver 탐색도 검증 범위 밖입니다.

Swift 포맷 수정:

```sh
xcrun swift-format format --in-place --recursive Package.swift Sources Tests
```

## 구조

```text
Package.swift          Swift Package Manager 설정
Sources/Chop/          앱 수명 주기, 창, 터미널 엔진과 입력 어댑터
Sources/ChopCore/      분할 트리, 검증 가능한 저장 형식과 원자적 파일 저장
Tests/ChopCoreTests/   분할·공간 이동·저장/오류 복구 테스트
Tests/ChopTests/       실제 셸과 다중 터미널 통합 테스트
Dependencies/         Ghostty 버전·어댑터 패치와 생성된 XCFramework
Resources/Info.plist   macOS 앱 메타데이터
scripts/              빌드, 실행, 검증
.github/              CI와 PR 템플릿
```

## 구현 순서

각 단계는 별도 브랜치와 PR로 진행합니다. 범위가 커지면 더 작은 PR로 나눕니다.

1. 보일러플레이트: 앱 실행, 빌드 스크립트, CI
2. 단일 터미널: libghostty 연결, 빈 칸 중앙 `+`로 셸 열기
3. 분할: 레이아웃 모델, 프리셋, 자유 분할, 크기 조절
4. 칸 관리: 포커스 이동, 확대·복귀, 닫기와 빈 칸 합치기
5. 복원: 레이아웃, 이름, 작업 경로 저장과 새 셸 복원
6. 후속 범위: 알림, Git 브랜치, CLI 연동

기여와 PR 절차는 [CONTRIBUTING.md](CONTRIBUTING.md)를 따릅니다.
