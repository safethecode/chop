# 사용자 교정: 기본 진입 화면

F-DEFAULT-01 / 2026-10-14 사용자 요청: 기본 터미널 하나를 열고 2·3·4는 +로 추가한다. 사용자가 제시한 [R-DEFAULT](../references/default-grid-user.png)를 직접 확인했다.
이전 내부 PASS는 단일 빈 칸으로 시작하는 흐름을 기본값으로 봤으며, 사용자가 원한 기본 실행 상태를 검증 조건에 넣지 못했다. 이 판정 누락을 수정한다. 기존 gate ledger와 이전 증거는 보존한다.

## 관찰 O와 적용 D

| 요소 | R-DEFAULT 관찰 | 적용/검증 계약 |
|---|---|---|
| E-D1 canvas | 2열×2행, 같은 너비/높이, 밝은 바탕 | 기본 LayoutNode grid, 재귀 splitter 재사용 |
| E-D2 좌상단 | 터미널 1·홈 표시, 셸 출력/프롬프트, 포커스 경계 | 첫 shell을 window 배치 후 자동 실행하고 포커스 |
| E-D3 나머지 | 터미널 2·3·4 헤더, 각 본문 중앙 원형 + | 시작 시 PTY가 없고 해당 버튼을 누른 뒤 하나씩 실행 |
| E-D4 헤더 | 이름/경로 왼쪽, 확대/닫기 오른쪽 | 기존 14pt/12pt/28pt 네이티브 컴포넌트 유지 |

제공 이미지는 1100×672 image px canvas crop이다. 창/toolbar가 보이지 않으므로 그 영역 제거를 요청했다고 추정하지 않는다. DPR/실제 point 크기는 미확인이다. 구현의 logical canvas 관계와 비교했으며 Last login 시각 같은 실제 셸 내용은 복사하지 않는다.

## 실제 재검증 V

macOS 26.5.2 Apple Silicon, 릴리스 앱, CUA AX와 실제 스크린샷을 관찰했다. 이 파일은 CUA 이미지 판독 기록이며 원본 PNG 내보내기가 아니다.

- 이전 앱에서 빈 칸 하나 상태를 저장하고 종료했다. 프로세스가 없고 저장 pane count=1, wasRunning=false임을 확인했다.
- 새 빌드를 실행하니 자동으로 grid가 선택되고 터미널 1의 프롬프트와 포커스가 나타났다. 2/3/4는 각각 중앙 + 하나씩 보였다. CUA 이미지는 전체 창 2200×1504 image px(2배 캡처)였으며, 상단 chrome을 제외한 canvas 관계가 사용자 crop과 같았다.
- 2번 + 클릭 후 실제 shell textArea 2개, 3번 클릭 후 3개, 4번 클릭 후 4개였다. 기본 첫 셸은 중간에 교체되지 않았다.
- 2/3/4를 닫아 다시 +로 돌리고 1번에 포커스를 두었다. 최종 화면은 요청 이미지의 실행/빈 상태와 일치했다.
- strict check: 9개 테스트 통과. fresh 생성의 4개 ID/이름, 최초 running count=1, 나머지 nil, startup 중복 호출 identity, 순차 2/3/4 실행, 기존 단일 빈 저장의 이름/cwd 유지, 사용 중 layout 복원까지 검증했다. 모두 빈 저장에서 마지막 빈 칸에 포커스가 있었어도 1번을 열고 1번으로 포커스를 옮기는 것을 확인했다.
- 기본 grid를 처음 붙일 때 일시적으로 0 높이가 전달되어 AppKit frame 경고가 있었다. 최소 크기 적용 전의 짧은 배치에서도 부모 영역 안에 frame을 두도록 수정했다. 같은 check를 다시 실행해 경고 없이 통과했다.

수정 범위는 기본 상태와 초기 배치이며 폰트/색/간격/버튼 디자인은 바꾸지 않았다. 새 사용자 screenshot은 이 기본 진입 영역에 한정한 reference다. 기존 cmux 외형을 재현했다는 의미가 아니다. 마우스 휠/전체 VoiceOver/macOS14 실기기는 이전과 같은 미검증 범위다.
