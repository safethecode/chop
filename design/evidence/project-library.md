# 최근 프로젝트와 작업 구성

2026-11-15, `a3a1b3b` main에서 만든 `feat/project-workspaces`의 셀프 리뷰. 외부 승인과 구분한다.
사용자가 승인한 개선 중 두 번째 작업이다. 첫 안정성 수정은 PR #43으로 머지했다.

## 범위와 결정

프로젝트 폴더를 다시 찾고 터미널/웹 칸을 매번 배치하는 일을 줄인다. 파일 메뉴 아래 최근 프로젝트와
프로젝트별 이름 있는 구성을 둔다. 기존48pt rail·32pt 추가 버튼·단일 옅은 경계와 canvas를 늘리지 않는다.
구성은 새 창에서 열어 현재 프로세스를 유지한다. 자동 세션과 다른 `projects.json`을 사용한다.

| 대상 | 정보와 동작 | 배치·토큰·검증 |
|---|---|---|
| E-P-menu | 최근12개 경로, 현재 프로젝트의 구성20개 이하, 저장/삭제 | native 파일 메뉴. 새 패널/장식/상시 설명 없음. 빈/1개/2개 실제 메뉴와20/100개 모델 한도 검사 |
| E-P-save | 이름과 저장 범위, 오류/수정/덮어쓰기 | 기존 InsetTextField/ChopStyle.font,300×28pt,14pt medium. blur inset과0.18초 전환을 기존 컴포넌트에서 상속. 부모 여백/버튼/제목은 native NSAlert |
| E-P-delete | 저장 항목 선택과 삭제 범위 | native NSPopUpButton300×28pt/14pt medium. 열린 창/프로젝트 파일은 유지 |
| E-P-open | 저장된 cwd·혼합 칸·트리 설정 | 새 window UUID, 기존 WorkspaceSnapshot 복원. 실제 pwd/새 셸/기존 셸 입력과 웹 문서 확인 |

간격 감사: 새 고정 간격을 추가하지 않았다. 이름·선택 입력의300×28pt는 기존 이름 변경 accessory의 치수를 보존했다.
OS가 배치하는 NSAlert/메뉴의 패딩·반경·버튼 크기는 native 예외이며 실측 CSS 값으로 쓰지 않는다.
테마·헤더·rail·원본 격자 배치는 미변경 속성이다. 사용자 교정의 넓은 rail/진한 이중 경계/파란 입력 ring을 재도입하지 않았다.

Do: 경로로 프로젝트를 식별, 구성의 프로젝트 범위 유지, 실패 입력 유지, 원본 파일 보호, 새 창/새 프로세스로 열기.
Avoid: rail 버튼/사이드바 추가, 기존 창 교체, 명령/환경변수 저장, 성공 토스트 반복, 장식 색·아이콘·구분선 추가.
Intentional differences: 이름 있는 구성이라는 새 과제를 기존 native 파일 메뉴/대화상자로 확장한다. 새 외부 UI의 픽셀 재현은 아니다.

문구의 즉시 행동·저장 범위·오류 원인을 제품 동작과 대조했다. 설명은 해당 저장/삭제/오류 순간에만 둔다.
새 앱 소유 문구는 한국어다. 파일명·URL·사용자가 연 셸/웹사이트의 문서는 기존 제삼자 콘텐츠 범위다.

## 실제 앱 관찰

정상 릴리스 바이너리를 복사한 `Chop 검증.app`에서 CUA로 실행했다. launcher가 `CFFIXED_USER_HOME`만
검증 임시 폴더로 지정해 세션/프로젝트 기록을 분리했다. 실행 중인 사용자 Chop(PID736)은 유지했다.
macOS26.5.2,1100×720pt content의 기본 창과 native 대화상자다. image-px와 pt를 등치하지 않는다.

- P-0: 변경 전 기본 라이트 화면·파일 메뉴를 확인했다. 파일 메뉴는 새 창/폴더 선택/클론이었다.
- P-1: 실제 알파 폴더를 선택해 새 창을 열고,첫 셸에서 환경변수를 설정하고 pwd를 확인했다. 둘째 터미널과 자체 HTTP 서버60571의 한글 웹 칸을 열었다. 메뉴를 열기 전⌘⇧S가 이름 입력창을 열었다.
- P-2:65자 한글을 저장하면 이름을 유지한 채1–64자 오류를 표시했다. 실제 라이트 스크린샷에서14pt 입력의 한 줄 수평 편집·중립 inset·native 저장/취소를 확인했다. 이름을 ‘알파 개발 환경’으로 수정해 저장했다.
- P-3: 웹 문서 입력을 채우고 파일 트리를 ‘소스’로 이동한 뒤 숨김·탭 보기·다크 모드로 바꿨다. 같은 이름 저장에서 대상과 갱신 범위를 표시했다. 실제 다크 확인창의 제목/본문/버튼 대비를 판독했다. 취소하면 이름이 남았고 다시 저장·덮어쓰기한 결과가 JSON에 반영됐다.
- P-4: 저장 구성을 골라 별도 창을 열었다. 웹 URL/탭 보기/숨긴 트리/두 셸이 복원되고 웹 입력은 새 문서의 빈 값이었다. 새 셸에서 `NEW=unset`과 알파 pwd를 확인했다. 원래 창의 웹 입력은 유지됐고,원래 셸에서 `ORIGINAL=kept`를 확인했다.
- P-5: 검증 기록 파일만 version999로 바꾼 뒤 ‘재시도 구성’ 저장을 시도했다. 한국어 새 버전 오류와 이름 유지,기존 바이트 불변을 확인했다. 검증 파일을 복구하고 같은 입력에서 저장을 재시도해 성공했다.
- P-6: native 삭제 popup에서 ‘재시도 구성’을 골라 삭제했다. 원래 구성1개·열린 창·셸 출력은 남았다. 최근 알파 항목은 새 기본4칸 창을 열었다. ‘목록 지우기’ 뒤 최근 목록만 비고 구성은 남았다.
- P-7: 검증 알파 폴더를 잠깐 이동하고 구성 열기를 실행했다. 전체 경로와 복구 안내를 표시하고 창 수4개를 유지했다. 폴더를 원위치한 뒤 검증 앱을 종료/재실행했다. 최근 이력은 여전히 비고 저장 구성이 메뉴에 남았다.
- P-8: 현재 빌드의 재실행 다크 기본4칸 화면을 직접 캡처하고 사용자 `default-grid-user.png`와 대조했다. 같은 두 열·두 행(각 비율 약1,시각 추정±0.01),첫 셸/빈 세 칸 중앙 plus/작은 조작 헤더를 유지한다. 원본의 과거 파란 pane 경계는 후속 사용자 교정으로 제거한 현재 계약을 따르며 헤더/트리/rail은 기존 확장이다. 대화상자와 메뉴가 canvas의 상시 공간을 차지하지 않는다.

메뉴는 AX 항목의 실제 실행으로 확인했다. CUA의 일부 연속 키 탐색에서 선택 변화가 관찰되지 않은 경우는 성공으로 세지 않았다.
실제 모든 물리 키 조합·VoiceOver·고대비·글자200%·Reduce Motion·모든 IME·macOS14 하드웨어는 새 성공으로 주장하지 않는다.
새 입력은 미변경 native 컴포넌트를 재사용하고 기존 상태/IME/동작 줄이기 검사도 전체 검사에서 실행됐다.
메뉴 최대 수량/극단 경로의 물리 포인터 검증은 모델 경계 검사와 구분한다. 개별 앱의 OS chrome은 기존 플랫폼 예외다.

- ProjectLibraryStore: 매번 읽기/검증 후 atomic 쓰기. 이름/배치 오류·손상·새 버전·4MiB 초과·실제 쓰기 실패에서 기존 바이트 보존.
- 네이티브 검사: 실제 메뉴 action→새 UUID 창,독립 surface·실제 pwd,기존 셸 환경,다른 프로젝트의 빈 구성 메뉴,창 닫기 후 구성 보존.

- 최초 선택 검사 fixture는 사용자 닫기 확인창을 열어 대기했다. 테스트 소유 창의 정리를 closeAll/close로 명시한 뒤 전체 검사를 완료했다. 제품의 실행 작업 확인 동작은 유지했다.
