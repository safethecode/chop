# PR #10 상단 아이콘 관찰

2026-10-14, macOS 26.5.2 / Apple Silicon, release Chop.app. 구현자가 수행한 셀프 리뷰다. CUA 실제 화면과 AX를 직접 판독한 기록이며, PNG 내보내기나 독립적인 승인으로 표시하지 않는다.

## 요청과 적용

사용자가 화면 모드를 선택하는 아이콘 버튼을 요청했고, 이어 `design/references/layout-controls-user.png`의 왼쪽 상단 레이아웃 선택도 아이콘으로 바꾸도록 요청했다. crop은 기존 글자 선택기의 위치·4개 선택지·선택 강조에 대한 근거다. 최종판은 그 관계를 유지하고 요청한 SF Symbols로 글자를 대체한다. 기존 기본 canvas 기준은 `default-grid-user.png`다. image-px와 macOS pt를 등치하지 않는다.

| ID | 실제 실행과 관찰 |
|---|---|
| E-I1 | 전체 창 약 1100×752pt에서 왼쪽 아이콘이 단일 사각형 / 좌우 / 상하 / 4분할로 보였다. AX에도 1칸 / 좌우 2칸 / 상하 2칸 / 4칸이 별도 라디오 버튼으로 나타났고 선택 값이 맞았다. |
| E-I2 | 1칸 → 좌우 → 상하 → 4칸을 실제 클릭했다. 각 그림과 실제 분할 방향이 일치하고 선택 항목 하나가 파란색으로 강조됐다. 기존 첫 셸을 그대로 유지했다. |
| E-I3 | 오른쪽 해 아이콘을 눌러 라이트로 전환하니 달 아이콘과 `다크 모드로 전환` AX 이름이 나타났다. 보기 메뉴에서 다크를 선택하니 해 아이콘과 `라이트 모드로 전환` 이름으로 갱신됐다. 버튼과 메뉴는 같은 AppDelegate 경로를 사용한다. |
| E-I4 | 위 배치/모드 전환 후 기존 셸에서 `TOOLBAR_STATE=preserved`를 실제 출력했다. 선택한 첫 칸과 셸을 유지하며 툴바 때문에 canvas 높이는 바뀌지 않았다. |
| E-I5 | 창을 640×441pt 전체 크기까지 줄였다. 다크·라이트 모두 왼쪽 네 아이콘, 오른쪽 편집 버튼과 모드 버튼이 겹치거나 잘리지 않았다. 4분할의 최소 본문 높이 180pt도 유지됐다. 검증 뒤 원래 1100×752pt 크기로 복구했다. |
| E-I6 | 아이콘으로 다크를 선택하고 앱을 완전히 종료했다. 프로세스가 없음을 확인하고 다시 실행하니 다크, 해 아이콘, 4칸 선택과 터미널 1 실행/2·3·4 중앙 +가 복원됐다. 테스트 과정에서 새로 생성된 빈 칸 이름은 2·3·4로 정리했고 처음부터 사용 중이던 1번 이름/cwd는 유지했다. |

모드 버튼은 기존 28×28pt ChopStyle.iconButton을 재사용한다. 레이아웃은 native NSSegmentedControl의 32pt 폭 segment와 14pt medium SF Symbols를 사용한다. toolbar 높이 48pt / 좌우 inset12 / 항목 간격12는 유지한다. `rectangle.split.2x1`은 좌우, `rectangle.split.1x2`는 상하로 실제 화면에서 방향을 대조했다. 새 모양/색/그림자/모션/장식은 추가하지 않았다. 캡처의 포인터 주변 표시 효과는 자동화 도구의 표시이며 앱 스타일이 아니다.

아이콘만 보인다는 요청을 지켜 상시 읽는 설명을 추가하지 않았다. 필요한 의미는 해당 조작의 tooltip·AX에 배치한다. 한국어 8원칙 중 즉시 행동 예측·핵심 정보·용어 일치·선택권을 대조했고 번역투/반복/추측성 약속은 없다. 감정적 공감이나 수치 안내는 이 조작에 해당하지 않아 추가하지 않았다.

## 검증 범위

`./scripts/check.sh` 통과: Swift strict format, shell syntax, plist, release build/signature, 기존 테스트 10개(3.333초). 실제 PTY 모드/레이아웃 보존 검사는 재실행했고, 얇은 아이콘 라우팅은 위 실제 앱에서 실행했다. 정적 아이콘 값을 반복하는 테스트는 추가하지 않았다. 소스는 AppDelegate의 공통 appearance 적용/저장 경로와 Workspace의 기존 프리셋 동작에 연결하며 새 엔진/분할 로직을 만들지 않았다.

기존 공통 75개 규칙과 프로젝트 조건을 검토했다. 변경한 toolbar의 의미·아이콘 출처·선택/모드 상태·접근성 이름·간격·최소 창·기존 canvas 관계를 새로 판독했다. 변경하지 않은 native 예외와 PTY/저장/스크롤 동작의 이전 근거는 보존한다. macOS 14 실기기·VoiceOver 전체 탐색·모든 TUI/입력기와 마우스 휠 자동화의 기존 미검증 범위는 늘려 주장하지 않는다.
