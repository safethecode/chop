# PR #12 헤더 배경 관찰

2026-10-14, macOS 26.5.2 / Apple Silicon, 구현자의 셀프 리뷰. CUA의 실제 화면을 직접 보고 기록했으며 독립 리뷰 승인이나 내보낸 PNG라고 표시하지 않는다.

사용자는 터미널 이름이 있는 헤더의 색을 달리해 달라고 요청했고, 각 칸별 다른 색 대신 **본문과 다른 배경색**이면 된다고 명확히 했다. 모든 헤더에 같은 모드별 중립 색을 적용한다. 글꼴·아이콘·포커스·헤더 높이와 기존 본문 팔레트는 유지한다.

| ID | 실제 실행과 관찰 |
|---|---|
| E-H1 | 새 빌드를 시작하니 사용자 비대칭 5칸(11·16·15·14·13), 실행 3개/빈 칸2개가 복원됐다. 다크에서 헤더 전체가 본문보다 조금 밝은 #292D35 역할로 구별됐다. 제목/경로/확대/닫기와 현재 칸 경계가 읽혔다. |
| E-H2 | 모드 아이콘으로 라이트를 선택했다. 모든 헤더가 연한 회색 #F3F4F6 역할, 본문은 흰색으로 바뀌었다. 빈 칸과 실행 칸 모두 같은 헤더 배경을 사용했다. |
| E-H3 | 편집 모드를 켜도 이동 손잡이·이름·경로·버튼이 같은40pt 헤더 안에 정렬됐다. 약295pt 폭의 작은 칸에서도 겹치지 않았고 본문 중앙 +와 구별됐다. |
| E-H4 | 터미널16을 확대해 라이트 헤더의 전폭 배경을 확인했다. 확대 중 다크로 바꾸고 전체 레이아웃으로 돌아오니 가려졌던 나머지4칸도 다크 헤더를 사용했다. 기존3개 셸의 프롬프트/Last login과 빈2칸 상태를 유지했다. |
| E-H5 | 검증 뒤 다크·전체5칸·일반 모드로 두었다. 새 빌드 적용을 위해 종료/재실행했으므로 셸은 새 프로세스다. 모드 전환 자체가 셸을 다시 열었다고 혼동하지 않는다. |

색의 HEX는 코드의 sRGB 값이며 스크린샷 픽셀을 역측정한 값이 아니다. 창 크기는 전체1100×752pt, 최소에 가까운 칸 폭 약295pt에서 확인했다. 이미지 px와 macOS pt를 등치하지 않는다. 40pt 헤더·12pt inset·28pt 조작부·14pt medium 글꼴과 각 칸의 기존 형상을 유지한다. 새로운 장식 구분선/그림자/아이콘/라벨은 추가하지 않았다. 헤더 색 면은 이름과 조작부가 소속되는 실제 영역이며 장식용 바가 아니다.

## 코드·검사

AppearanceMode.headerBackground를 TerminalPaneView.applyAppearance에서 소비한다. 헤더의 layer backing을 configureViews에서 준비한 뒤 초기 모드와 이후 갱신에 같은 경로를 사용한다. 새 칸도 같은 초기화 경로를 사용하고 Workspace가 가려진 칸까지 갱신한다. TerminalView/Ghostty의 layer 생성 순서는 건드리지 않는다. 전체 칸 드래그 미리보기는 기존 실제 헤더 bitmap을 사용하므로 헤더 배경도 포함된다.

`./scripts/check.sh` 성공: 11개 테스트 4.321초, strict Swift format / shell syntax / plist / release build / 서명 검증 통과. 새 정적 색상 값을 그대로 반복하는 테스트는 만들지 않았다. 기존 실제 PTY/두 모드/칸 교환/전체 preview/복원 테스트를 재실행했고, 변경한 색 면·가독성·숨긴 칸 모드 전환은 위 실제 앱에서 확인했다. 로그는 로컬 `.cache/check-header-background.log`다.

기존87개 규칙과 헤더 조건을 검토했다. 본문보다 다른 배경을 원하는 사용자 요청이 해당 색 역할의 근거다. 기본 canvas와 toolbar/중앙+ 관계를 유지하고, 현재 사용 중인5칸을 초기4칸으로 되돌리지 않는다. 바뀌지 않은 native 예외·미적용 사유·이전 실제 근거는 보존한다. macOS14 실기기·VoiceOver 전체 탐색·모든 입력기/TUI·하드웨어 휠의 검증 범위를 확대하지 않는다. 이번 변경은 읽는 문구를 추가하거나 수정하지 않는다.
