# 내부 통신 포트의 웹 주소 오인 수정

2026-11-17, Codex 셀프 리뷰. 독립 리뷰나 출시 승인으로 표현하지 않는다.

## 요구와 원인

사용자는 개발 서버가 `localhost:3000`인데 Chop이 `http://localhost:50252/`를 표시한다고 보고했다.
실제 `lsof`에서50252의 listener는 `codex` 실행 파일의 소유임을 확인했다.
기존 구현은 셸 아래 모든 로컬 TCP listener를 주소로 표시했고, HTTP인지 확정하는 기능은 없었다.

`LocalServerDiscovery`는 프로세스 실행 파일 경로의 마지막 요소가 정확히 `codex`인 경우
그 프로세스의 listener 수집만 생략한다. 자식 탐색·PID/시작 시각 재확인·종료 제거는 유지한다.
경로 조회 실패 시 기존 탐색을 유지한다. 모든 도구나 HTTP 서비스의 일반 판별을 구현했다는 주장은 하지 않는다.

## 실제 앱 관찰

동일 release 바이너리를 복사한 격리 `Chop 검증.app`에서 CUA로 실행했다.
검증용 home만 `CFFIXED_USER_HOME`으로 분리했다. 사용자 Chop(PID67582)의 터미널은 유지했다.

- S-0: 기존 사용자 앱은 Codex만 실행 중인 칸에도50000대 주소를 표시했다. 해당 포트의 프로세스 정보를 별도로 확인했다. 기존 앱에는 입력·종료를 하지 않았다.
- S-1: 검증 실행 파일 `codex`가 임의 포트의 listener와 자식 Python HTTP 서버3000을 함께 열었다. 라이트 격자 헤더는 `localhost:3000`만 표시했고, 내부 포트나 추가 개수는 표시하지 않았다.
- S-2: 실제 주소 버튼을 눌렀다. 같은 창의 빈 칸에 웹 페이지가 열렸고, 주소 입력·페이지 URL·서버 요청 로그 모두 `http://localhost:3000/`였다.
- S-3: 다크 모드와 탭 보기로 바꾸고 원래 터미널을 선택했다. 탭 오른쪽에도 `localhost:3000`만 표시했다. 기존 헤더 높이/글자/옅은 rail 경계/파일 트리/인셋 입력 표면을 현재 화면과 대조했다. 새 컨트롤·색·문구는 없다.
- S-4: 검증 프로그램에 Enter를 보내 자식 서버와 내부 listener를 종료했다. 같은 탭의 주소 버튼이 다음 감지 주기에 사라졌고 셸 입력으로 돌아왔다.

직접 확인한 CUA 이미지와 AX 상태를 기록한 문서다. 별도 PNG 파일이나 전체 보조 기술 실행을 주장하지 않는다.
원본 default-grid-user.png와의 동등 격자 관계는 이번 변경에서 수정하지 않았으며 기존 원본·후속 사용자 교정을 보존한다.

## 자동 검사와 한계

- 실제로 컴파일한 `codex` 프로세스의 내부 listener를 제외하면서 자식 서버를 남기는 회귀 검사를 추가했다. 단독 검사는 통과했다.
- `./scripts/check.sh`의 strict lint·release 빌드·서명 검증·아이콘 검증은 통과했다. 전체 검사는 기존 `savedProjectConfigurationOpensANewWindowAndPreservesTheExistingShell`에서 `NSPasteboard.general`이 null인 실행 환경 오류로 중단됐다. 통과로 표시하지 않는다.
- GitHub의 최신 main이 기존f825264와 같음을 fetch로 확인했다. 기본 DNS 조회 및 CLI의 Keychain/인증 접근에 문제가 있어 PR·CI·머지는 아직 수행하지 못했다. 인증 정상화 후 원래 전체 검사와 CI를 완료해야 한다.

변경된 주소 표시/클릭/종료의 실제 앱 범위는 aligned. 전체 검증·통합 완료와 구분한다.

후속: 사용자가 실행한 게시 스크립트도 같은 클립보드 초기화 충돌에서 중단됐다. lazy nullable 조회로
signal6을 수정하고 현재 전체62개 실행과 남은 native 서비스 실패를 [별도 근거](clipboard-service.md)에 기록했다.
원래 S-0–4의 주소 UI 관찰과 이후 클립보드/검사 실행 조건의 변경을 구분한다.
