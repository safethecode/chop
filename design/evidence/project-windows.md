# 프로젝트별 독립 윈도우

2026-10-20 Codex 셀프 리뷰. 외부 리뷰나 승인이 아니다. 사용자는 Ghostty처럼 터미널에서
명령을 실행하지 않고 프로젝트마다 Chop 창을 열기를 요청했다. 첨부 임시 이미지 경로는
OS 권한으로 읽지 못했으므로 이미지를 대조했다고 주장하지 않는다. 설명된 동작과 기존
Chop 네이티브 메뉴·창·폴더 선택기를 비교 기준으로 삼았다.

Q-WINDOW: 파일 메뉴/⌘N과 프로젝트 폴더에서 새 윈도우/⌘⇧N, 같은 Dock 메뉴를 추가했다.
새 윈도우는 활성 셸의 cwd를 이어받고 폴더 선택은 새 창의 셸·트리 시작 경로를 정한다.
제목은 폴더 이름 — Chop, 창 전환은 macOS 윈도우 메뉴다. 별도 사이드바·카드·설명·상시
CTA를 추가하지 않았다. native 메뉴/선택기 글자 크기 예외를 유지한다. 실제 native
새 창·폴더 선택·선택 취소·창 전환을 실행했다. adapted-and-verified.

Q-INDEPENDENT: 각 창은 다른 WorkspaceView·NSWindow·PTY·설정 suite를 사용한다.
터미널/레이아웃/파일 메뉴 명령은 key/main window의 작업 공간을 대상으로 한다.
화면 모드는 앱 전체다. 창 닫기는 해당 창의 작업만 확인하고 닫으며 앱 종료는 모든
창의 작업을 확인한다. 창별16칸 한도는 유지하며 창 수를4개로 제한하지 않는다.

Q-RESTORE: v2 ApplicationSnapshot에 열린 창 목록·선택 창과 각 v1 workspace를 원자 저장한다.
기존 단일 v1을 첫 창으로 읽고 파일 트리 환경설정도 이 창으로 이전한다. 창별 트리 루트·폭·
표시는 별도 defaults에 저장한다. 닫힌 창은 복원 목록에서 제외하며 앱 종료 때 남은 창을
다음 실행에서 새 셸로 연다. 명령·환경변수·기존 프로세스를 복원한다고 주장하지 않는다.
4MB 저장 제한·중복 ID/잘못된 focus/경로/버전 거부·손상 파일 보관과 쓰기 실패 처리는 유지한다.

## 실제 앱 관찰

원래 실행 중인 Chop에 다른 작업이 있어 종료하지 않았다. 별도 bundle ID와
ChopVerification/session.json을 쓰는 검증 앱을 사용했다. 제품 소스 차이는 세션 경로뿐이다.

- E-WIN-1: 기존 단일 저장에서 첫 창과 Sources 파일 트리 경로가 유지됐다. ⌘N으로 두 번째
  독립 창을 만들었다. ⌘⇧N의 native 폴더 선택기로 chop을 골라 chop — Chop 창을 열었다.
  셸 pwd 출력과 파일 트리 모두 /Users/aaron-son/Documents/chop였다.
- E-WIN-2: chop 창에서 환경변수를 설정한 뒤 Sources를 골라 별도 창을 만들었다.
  이 창의 셸/트리 경로가 Sources인 것을 AX로 확인했다. ⌘⇧W로 Sources 창을 닫은 후
  chop 창에서 실제 PROJECT=kept 출력을 확인했다. 입력 에코만으로 보존을 판단하지 않았다.
- E-WIN-3: 세 창을 연 상태로 종료/재실행해 윈도우 메뉴의 세 창 목록과 활성 chop 창,
  첫 창 Sources 트리와 chop 창의 서로 다른 트리 경로를 확인했다. 첫 창에서 라이트로
  바꾼 후 다른 chop 창도 라이트로 표시됐다. 1100×752px 실제 두 모드 본문/헤더/메뉴와
  좁힌48pt 추가 영역을 판독했다. px와 content pt를 등치하지 않는다.
- E-WIN-4: 모든 창을 닫아 session.json의 windows가0개가 되고 앱 프로세스가 남아 있는
  것을 확인했다. 이어 ⌘N으로 하나를 다시 열고 저장 windows1개/실제 창을 확인했다.
  이 창의 셸을 Sources로 cd한 뒤 ⌘N을 누르자 새 창 제목·셸/빈 칸 cwd·파일 트리 모두
  Sources가 됐다. ⌘T는 이 창의 두 번째 셸을 열었고 첫 창은 하나를 유지했다. 실제 AX와
  저장 metadata로1개/2개 셸을 확인했다. 프로젝트 선택기를 취소해 기존 창이 유지됐다.

## 코드와 자동 검사

저장 형식 검사는 기존 파일을 로드만 할 때 바꾸지 않는 이전·다중 창 roundtrip·빈 창 목록·
중복/잘못된 focus/상대 경로/과대 저장 거부 시 마지막 정상 파일 보존·손상 원본 보관을
검증한다. 실제 셸 통합 검사는 서로 다른 프로젝트 두 창·PTY·cwd·트리·활성 창·이름과
snapshot·복원을 확인한다. A에서 sleep 작업이 실행되는 동안 B를 활성화하면 앱 전체
종료 확인은 필요하지만 B 창 닫기는 확인이 필요 없으며 A의 완료 출력과 환경변수가
보존되는 것을 검증한다. 테스트의 패널 가시성은 격리해 CI 물리 화면에 의존하지 않는다.

셀프 리뷰는 명령 대상 선택·창 닫힘 콜백/메모리 소유권·앱 전체 종료/화면 모드·저장
취소/오류 보존·이전 형식·창별 defaults 분리를 확인했다. 관련 없는 파일 드래그·전체
VoiceOver·고대비/Reduce Motion·macOS14 실기기는 새 검증으로 표시하지 않는다.

E-WIN-5: 최종48pt/32pt·옅은 경계·트리 오른쪽 중복 선 제거를 합친 앱에서 재실행했다.

## 자동 리뷰 후 설정 수명 수정

V-55 / E-WIN-6: CodeRabbit의2549298 자동 리뷰에서 사용자 닫기 후 창별 defaults와
frame 저장값이 남는 introduced P2를 지적했다. 셀프 검토로 재현 경로를 확인하고 사용자
닫기에서만 같은 suite를 정리하도록 바꿨다. 테스트의 custom factory에는 matching cleanup을
주입한다. shutdown은 정리를 호출하지 않으므로 다음 실행에 복원할 창의 설정을 보존한다.

새 회귀 검사의 최초 실패에서 window의 autosave 이름이 비어 있음을 확인했다.
SDK NSWindowController.h는 initWithWindow가 컨트롤러의 autosave 이름을 window에
설정한다고 명시한다. 기존 초기화 순서에서 먼저 준 이름이 지워지므로 super.init 뒤
controller.windowFrameAutosaveName을 설정하도록 고쳤다. 닫기에서는 autosave 등록을
해제한 뒤 NSWindow.removeFrame으로 같은 이름의 위치 저장값을 제거한다.

최종 ./scripts/check.sh 전체38개 통과. 실제 셸 통합 검사에서 이름이 비어 있지 않음과
실제 frame 저장 키 생성, B 닫기 후 B suite/frame 삭제·A frame 유지, A/C를 앱 종료 방식으로
닫은 후 suite/frame 유지와 두 창 복원을 확인했다. 닫기 전의 오래된 snapshot으로 B를
다시 여는 검사는 앱의 실제 복원 경로와 달라, B를 제외한 현재 두 창 snapshot을 복원하도록
바꿨다. 다른 창 작업/ENV 보존 검사는 유지했다.

실제 최종 검증 앱에서도 두 창 중 Sources 창을 닫았다. session 목록에서 그 ID가 빠지고
해당 suite의 루트·해당 frame 키가 삭제된 것을 defaults 읽기로 확인했다. 남은 창에서
⌘N이 같은 Sources 폴더의 새 창을 열었다. 앱 종료 후 저장된 두 창의 루트/frame 키는
모두 남았고 재실행의 윈도우 메뉴에 aaron-son/Sources 두 창이 표시됐다. 닫기 직후 남은
창의 AX 조회는 CUA 시간 초과가 났으며 sample의 앱 main thread는 정상 이벤트 대기였다.
이 즉시 AX 관찰은 성공으로 표시하지 않는다. 설정 정리·새 창 실행·종료/재실행은 위 별도
관찰로 확인했다. 원래 Chop 작업은 종료하지 않았다.

자동 리뷰는 외부 사람의 승인으로 표현하지 않는다. 수정 후 셀프 리뷰와 위 검증으로
fixed-and-verified (설정 수명 범위). UI 색·치수·메뉴는 바꾸지 않아 앞선 시각 관찰을
유지하며 새 화면 검증으로 확대하지 않는다.
