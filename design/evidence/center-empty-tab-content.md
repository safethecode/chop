# 빈 탭 중앙 추가 버튼

- R-TAB-CENTER: 사용자 제공 917×756 이미지 crop에서 탭 바는 상단 약40px이고 `+`는 약(687,600)에 있었다. 본문 중심은 약(458,422)이므로 버튼이 오른쪽 아래로 치우쳐 있다. image px 관찰이며 native pt 등치가 아니다.
- E-TAB-BODY / O: 상단 탭 바와 선택 본문은 형제이고, 본문이 남는 전체 폭/높이를 채운 뒤 그 안에서56pt 원형 버튼을 중앙 정렬해야 한다. 기존 실행 앱에서도5는 오른쪽 아래,7은 왼쪽 아래에 남는 것을 직접 관찰했다. 선택 탭 이름·버튼 문구·아이콘·색상 변경 요청은 아니다.
- D: 선택 pane을 Auto Layout으로 새 일반 컨테이너에 붙이던 경계를 전용 TerminalTabContentView로 교체했다. 다른 native split과 같이 resizeSubviews에서 탭 바40pt/나머지 본문 프레임을 동기 적용한다. 기존 pane과 PTY는 그대로 재사용한다. 몸체 안의 중앙 버튼 제약은 유지한다. 이 변경은 tab content 배치이며 직전 스크롤 PR25와 분리했다.
- 최초 검사 한계: 비표시 NSWindow의 geometry 검사는 수정 전에도 통과해 실제 실행 앱의 프레임 지연을 재현하지 못했다. 이를 실패→성공 자동 재현이라고 주장하지 않는다. 실제 실행 앱의 탭 전환에서 최초 결함을 관찰하고 최종 실행 앱에서 다시 판독했다.
- V: 최종25개 검사/check.sh/릴리스 번들 서명 검증 통과. 새 geometry 검사는 격자→탭 재부착,917×756/640×400 변경,다른 빈 탭 왕복 뒤 pane과 실제 clip 크기·본문 중심을 비교한다. 기존 legacy/overlay70회 경계와 실제 셸 통합 검사도 포함한다.
- 실제 앱: macOS에서5/7/8 빈 탭이 같은 본문 중앙에 오는 것을 확인했다. 파일 트리 열림/닫힘,1100pt 창과680pt 축소·재확대,다크/라이트,격자→탭 왕복 뒤에도 중앙이고 외부 canvas 손잡이가 불필요하게 남지 않았다. 최종 dark2200×1504 raw screenshot의 본문은y240..1504,버튼 중심은약(1100,872),light1360×882 본문y240..882의 중심약(680,561)과 맞는다. 로컬 원본 .cache/chop-tab-centered-dark.jpg / .cache/chop-tab-centered-light.jpg. 원본 이미지는 편집하지 않았다.
- 영향 판독: 공통 툴바/탭 순서/40pt 헤더/56pt 주 행동/기존16칸 및 이름·경로·열림 상태는 유지한다. 키보드 focus 전 새 본문 크기를 적용하고 불필요한 전역 설정 변경·장식 추가는 없다. 과거 스크롤/탭/아이콘 예외와 실패 기록은 보존한다.
