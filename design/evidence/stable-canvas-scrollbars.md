# 리사이즈 스크롤바 안정화

- 사용자 교정: viewport를 줄이거나 키울 때 스크롤바가 생겼다가 사라져 화면이 흔들린다. 이름 변경 PR의 native 검증 중에도 처음 창/보기 전환에서 불필요한 두 축과17pt 빈 가장자리를 관찰했다. 이름 변경 작업은 별도 브랜치에 보관하고 최신 main에서 이 수정만 분리했다.
- 원인/재현: 이전 구현은 이전 contentView 크기로 문서를 계산하고 main queue 다음 갱신에서 다시 맞췄다. native tile 시점에는 문서가 이전 크기여서 legacy 손잡이가 공간을 차지했다가 다시 해제됐다. 기존50ms 뒤 안정화 검사만으로는 순간의 결함을 놓쳤다. 새 회귀는 실제 tile 직후를 검사하며 수정 전6개 assertion 실패를 확인했다. 예:561×361 viewport에17pt gutter가 남고 문서는570×370이었다.
- 수정: 전체 bounds와 최소 문서에서 매번 gutter 없는 상태로 시작해 필요한 축을 최대3단계로 계산한다. 크기는 설치된 AppKit의 contentSize API를 사용해 legacy/overlay를 구분한다. 자동 숨김에 따른 되먹임 대신 필요한 hasHorizontal/VerticalScroller만 켠다. 자연스러운 tile 요청에서 문서를 먼저 맞춘 뒤 super.tile을 호출한다. NSView.layout 안에서 수동 super.tile 반복을 돌리지 않으며, 문서 갱신의 재진입은 guard한다. 기존 비동기 반복 예약은 제거했다.
- 자동 검사: 최초 회귀 FAIL→수정 후 PASS. 두 native 스타일에서 들어감/가로만/세로만/양축/한 축 gutter로 다른 축도 필요한 경계/정확한 최소 크기/재확대를70회 동기 변경하는 회귀도 통과했다. 실제 셸을 포함한 전체24개 테스트5.012초 및 check.sh 전체 통과. 로그는 로컬 .cache/test-scroll-gutters-before.log, .cache/check-stable-scroll.log다.
- 실제 창: macOS26.5.2에서 한 실행 셸+세 빈 칸을 유지했다. 기본1100×752와 격자 최소842×442를 다크/라이트에서 확인하고, 이후 실제 포인터로3회 추가 축소/확대하여 각 끝 상태의 AX에서 canvas 스크롤바 없음과 연속된 문서 경계를 확인했다. 두 모드 최소 창의 스크린샷도 직접 판독했다. 드래그의 모든 중간 프레임을 별도 녹화한 검증은 아니다.
- 보기 회귀: 최소 창에서 좌우는 가로 손잡이만, 상하는 세로 손잡이만, 각 격자 복귀 뒤에는 없음. 탭 최소683×432에서 외부 canvas 손잡이 없음. 파일 목록의 세로 스크롤은 실제 내용에 따른 별도 동작으로 유지한다. 한 칸 확대/복귀·파일 트리 개폐 뒤에도 외부 불필요한 축이 없었다.
- 수명/복구: 시작한 셸에 CHOP_RESIZE_CHECK=kept를 설정하고 모든 전환·크기 변경 뒤 RESIZE_FINAL=kept를 실제 출력했다. 검증용 변수는 지우고 기존 이름6/5/7/8·다크 격자·다운로드·첫 셸 포커스로 복원했다. 새 Chop crash report는 없고 기존021751 기록만 남는다. 여러 실행 셸의 수명/입력 회귀는 기존 실제 PTY 통합 테스트 범위다.
- 범위: 앱의 canvas sizing만 수정했다. 터미널의 스크롤백, 파일 목록, 탭 목록의 별도 스크롤과 macOS 전역 설정은 바꾸지 않는다. 앱 전체/VoiceOver/macOS14 실기 검증을 새로 완료했다는 판정은 아니다.
