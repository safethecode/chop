# 최종 실제 화면·행동 관찰

2026-10-14, macOS 26.5.2 / Apple Silicon, 릴리스 앱. 최종 스크롤 메뉴 코드를 포함한 빌드에서 CUA의 실제 스크린샷과 AX를 관찰했다. 이 파일은 이미지의 판독 기록이다. 원본 PNG를 내보냈다고 주장하지 않는다. UI는 실행 중인 세 셸과 빈 칸 하나, 680pt 비대칭 경계를 가진 4칸 작업 공간이었다. 기본 콘텐츠 크기는 1100×720pt이다.

## 스크롤과 선택

1. 실제 셸에서 `printf 'CHOP_최종_스크롤_OK\n'; seq 1 80`을 실행했다.
2. `⌘↑`: Last login, 실행 명령, 한글 출력, 1~11행이 화면에 보였다.
3. `⇧Page Down`: 12~25행이 보였다.
4. `⇧Page Up`과 `⌘↓`: 마지막 68~80행과 프롬프트가 보였다.
5. 68행 숫자를 마우스로 드래그했다. 해당 숫자만 선택 배경으로 표시됐다. 테스트 클립보드를 사용하는 복사/붙여넣기는 PTY 통합 테스트에서 별도로 통과했다.

이 결과는 CUA scroll API의 오류를 마우스 휠 통과로 바꾼 것이 아니다. **마우스 휠 실기 동작은 미검증**이며 입력 연결 코드만 확인했다. 키보드/메뉴 동작과 실제 viewport 이동을 별도로 검증했다.

## 공통 UI 회귀

- 헤더 확대 버튼의 왼쪽 가장자리 근처를 클릭했다. 해당 칸만 확대됐으며 닫기가 실행되지 않았다. 확대된 헤더의 복귀 버튼 가장자리로 원래 4칸으로 돌아왔다.
- `⌘⇧L`로 편집을 켰다. 실행 칸 중앙에는 추가 버튼, 빈 칸 중앙에는 열기 버튼이 보였다. 추가 메뉴에서 오른쪽을 선택하니 `/tmp`를 상속한 다섯 번째 실제 셸이 생겼다. 기존 화면과 출력은 유지됐다.
- `⌘W` 두 번으로 새 셸을 닫고 빈 칸을 제거했다. 원래 4칸 모양과 680pt 경계가 복구됐다.
- `sleep 20` 실행 후 `⌘W`: 취소/터미널 닫기 네이티브 확인창이 표시됐다. 실제 화면에서 제목·영향 문구·버튼 둘이 잘리지 않았다. 취소하고 Ctrl+C 후 방향키로 옆 칸에 이동했다.
- 메인 콘텐츠는 흰색이며 네이티브 제목 막대/경고창은 시스템 appearance를 따른다. 추가 버튼은 SF Symbols plus이고, 확대/복귀와 닫기도 같은 네이티브 아이콘 계열이다. 작업을 설명하는 별도 로고·슬로건·카드·상태 배지를 만들지 않았다.
- 헤더 이름/경로는 같은 14pt medium 코드 토큰을 사용하며 좌우 12pt 정렬을 유지했다. 조작 영역은 28×28pt, 중앙 추가는 56×56pt다. 실제 클릭은 가까운 두 동작을 동시에 실행하지 않았다. 소수/빈 칸에 별도 스크롤바가 생기지 않았다.
- 최소 창과 긴 이름은 PR #4에서 실제 관찰했고, 해당 헤더 레이아웃/스타일은 이후 변경하지 않았다. 복원/정상 종료/폴더·파일·권한 오류는 PR #5에서 검증했다. 최종 변경은 스크롤 메뉴와 binding 연결이며 다른 화면 레이아웃을 바꾸지 않았다.

범위: macOS 14 실기기, 전체 VoiceOver, 모든 IME, 휠 자동화는 검증하지 않았다. 사이트·모바일·Figma 픽셀 재현 작업이 아니며 cmux의 화면과 동일하다고 주장하지 않는다. 최종 판정의 예외는 `gate-contract.json`에 명시한다.
