# 복원 기능 실제 앱 관찰

2026-10-14, macOS 26.5.2 / Apple Silicon. CUA로 릴리스 앱을 실행하고 AX 상태와 실제 스크린샷을 관찰했다. 이 파일은 대화에 표시된 이미지의 관찰 기록이며 PNG 원본으로 표시하지 않는다.

## 정상 종료와 새 셸 복원

- 4칸 중 3칸을 열고 1칸은 비웠다. 첫 칸 이름 `서버`, 경로 `/tmp`, 분할 경계 680pt로 바꿨다. 셸 변수 `CHOP_RESTORE_UI=old_shell`과 명령 완료 출력을 확인했다.
- 저장 파일의 해당 ratio는 0.618744313011829, 열림 상태는 `[true, true, true, false]`였다. 앱 종료 직후 파일은 종료 전과 동일했다. 종료 시 닫는 과정이 열림 상태를 덮어쓰지 않았다.
- 재실행하니 `서버 /tmp`, 680pt 경계, 선택한 첫 칸, 세 셸과 마지막 빈 칸이 복원됐다.
- `printf 'RESTORED=%s\\n' "${CHOP_RESTORE_UI-fresh}"; pwd` 실행 결과는 `RESTORED=fresh`와 `/tmp`였다. 이전 셸 상태/명령이 재실행된 것이 아니다.

## 발견과 수정

- 실제 PTY 복원 테스트에서 초기 배치 알림이 ratio 0.5를 약 0.745로 변경하는 실패를 포착했다. NSSplitView가 사용자 마우스 추적 중일 때만 비율을 기록하도록 수정했다. 재실행된 실제 화면의 680pt 경계와 저장 비율이 일치했다.
- 동시 복원 첫 화면에서 일부 글리프가 보이지 않는 것을 관찰했다. 처음에는 실제 칸 크기 초기화/픽셀 갱신을 조정했으나 첫 재검증에서 문제가 남았다. 업스트림 Metal.zig의 layer-hosting 순서를 확인하고 surface 생성 전 wantsLayer 설정을 제거했다. 그 다음 새 빌드에서는 세 칸 모두 `Last login` 전체와 프롬프트가 정상 렌더링됐다. 실패한 첫 수정도 이 기록에 보존한다.

## 오류 복구

- 실행 칸/빈 칸에 존재하지 않는 폴더 두 개를 저장하고 재실행했다. 알림 한 번에 두 경로가 나왔으며 확인 후 둘 다 홈 폴더로 대체됐다. 빈 칸은 열리지 않았다.
- 읽기/실행 권한도 검사하도록 보완한 최종 빌드에서 ‘이전 작업 폴더를 열 수 없어요’ 알림의 실제 화면을 확인했다. 경로는 줄바꿈되고 확인 버튼과 본문이 잘리지 않았다.
- 의도적으로 잘못된 JSON 바이트를 넣었다. 재실행 알림에 `session-unreadable-<UUID>.json` 보관 위치가 나왔고, 확인하면 단일 빈 칸을 사용할 수 있었다. 보관 파일의 바이트가 원래 오류 파일과 동일함을 파일 검사로 확인했다.
- 앱 전용 저장 폴더를 잠시 0500으로 바꾸고 4칸 프리셋을 골랐다. 저장 권한 오류 알림과 재시도 메뉴 안내가 나왔다. 종료할 때 미저장 확인이 나왔고 취소하면 작업 공간이 유지됐다. 폴더를 0700으로 복구하고 터미널 메뉴의 ‘레이아웃 다시 저장’을 실행했다. 파일에 4칸이 저장되고 파일 모드는 0600이었다.
- 검증 후 정상 스냅샷과 저장 폴더 권한을 복구했다.

## 범위

9개 로컬 테스트, 릴리스 빌드/서명 검사도 통과했다. 최신 빌드에서 한글 명령 출력과 80줄 출력을 실행했다. CUA의 native scroll 호출은 `noWindowsAvailable` 오류를 내 실제 마우스 휠 검증은 수행하지 못했다. 앱은 계속 실행 중이었고 크래시 보고서는 없었다. 스크롤 입력 코드를 확인했으나 이 사실을 마우스 휠 검증 통과로 바꾸지 않는다. 후속 키보드 스크롤 검증에 연결한다.

macOS 14 실기기와 전체 VoiceOver 탐색은 범위 밖이다.
