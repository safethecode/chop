# PR #8 화면 모드 관찰과 코드 검토

2026-10-14, macOS 26.5.2 / Apple Silicon, release Chop.app. 구현자가 수행한 셀프 리뷰다.
CUA의 실제 NSWindow 스크린샷과 AX 상태를 직접 관찰했다. 이 파일은 관찰 기록이며 캡처 PNG 파일이나 독립적인 리뷰 승인이 아니다.

## 요구와 화면 비교

사용자는 기존 기본 4칸에 더해 라이트·다크 모드를 요청했다. 사용자 원본 `design/references/default-grid-user.png`는 canvas crop이다.
원본과 최종 라이트 화면을 대조해 2×2, 좌상단 셸 하나, 나머지 세 중앙 `+`, 이름/경로와 우측 확대·닫기를 유지했다.
다크는 동일한 구조에 명시적으로 요청된 색상 변형을 적용했다. toolbar/header 높이·간격·글꼴·버튼 치수는 바꾸지 않았다.
실제 창 콘텐츠는 약 1100×720 macOS pt이며 전체 창 캡처에는 제목 막대가 포함된다. 원본 image-px와 pt를 등치하지 않는다.

## 실제 화면과 행동

| ID | 실행과 관찰 |
|---|---|
| E-A1 | 새 빌드의 라이트 화면: 흰 콘텐츠와 터미널, 어두운 이름·프롬프트, 세 개의 중앙 원형 +. 기존 사이드바 없는 구조와 우측 헤더 조작을 유지했다. |
| E-A2 | 보기 → 다크 모드: 창/toolbar/네 칸이 즉시 어두워지고 이름·경로·실제 터미널 출력·커서가 읽혔다. 첫 칸의 기존 출력이 남았고 빨강·초록·파랑 ANSI 출력도 실제 확인했다. |
| E-A3 | 다크에서 2번 +를 눌러 새 셸을 열었다. 새 셸도 어두운 배경에 정상 Last login/프롬프트를 표시했다. 2번을 확대한 상태에서 라이트로 전환하고 복귀하니 숨겨졌던 1번과 빈 3·4번까지 밝아졌다. |
| E-A4 | 라이트 → 다크 → 라이트 → 다크 반복 후 원래 셸에서 명령을 실행해 `AFTER_SWITCH=preserved`를 확인했다. 이전에 설정한 셸 변수가 유지됐다. 레이아웃·선택 칸·확대 상태는 전환 자체로 바뀌지 않았다. |
| E-A5 | 다크에서 이름 변경 대화상자를 열었다. 다크 표면의 제목·설명·입력 필드·취소/변경 버튼이 읽혔다. 취소해 이름과 셸을 유지했다. 다크 편집 모드의 중앙 추가와 오른쪽/아래 방향 메뉴도 열고 취소했다. |
| E-A6 | 테스트로 연 2번 셸을 닫고 1번에 포커스를 둔 뒤, 다크 선택 상태로 앱을 완전히 종료했다. 프로세스가 없음을 확인한 뒤 다시 실행하니 다크로 네 칸과 첫 새 셸을 복원했다. 라이트를 선택해 같은 종료/재실행을 반복하니 라이트로 복원했다. 최종 상태는 라이트, 첫 셸 하나와 세 +다. |

| E-A7 | 실제 출력 한 줄을 마우스로 드래그해 선택했다. 라이트의 연한 선택 배경에 어두운 글자가 읽혔고, 선택한 상태로 다크 전환 후에도 같은 선택이 남아 어두운 선택 배경/밝은 글자로 읽혔다. 라이트로 돌아와 테스트 출력을 clear했다. |

헤더 40pt, inset/row 12pt, toolbar 48pt, 헤더 조작 28pt, 중앙 + 56pt를 그대로 소비한다. 포커스는 외곽 한 줄이며 모드 전환으로 글자 줄바꿈·칸 크기를 변경하는 별도 제약을 만들지 않았다. 경로는 기존 중간 말줄임/전체 툴팁을 유지한다.
라이트/다크 모두 평면 중립 배경, 네이티브 조작과 선택 accent를 사용한다. 임의 로고·카드·배지·장식 구분선·자체 그림자·그라디언트·애니메이션은 추가하지 않았다.

## 코드·검증 근거

- AppearanceMode는 두 모드의 chrome 색과 AppKit appearance를 정의하고 UserDefaults에 선택을 저장한다. 알 수 없는 저장값은 기존 라이트 기본값으로 복구한다.
- TerminalEngine은 번들 공통 설정과 두 팔레트를 시작 시 모두 검증한다. pinned Ghostty의 `App.updateConfig`는 기존 모든 surface 설정을 갱신하고 embedded runtime은 앱 config를 clone해 이후 새 surface에도 사용한다. 로컬 공식 pinned 소스 App.zig/Surface.zig/apprt/embedded.zig에서 이 동작을 확인했다.
- 약한 TerminalView 목록은 숨긴 surface까지 light/dark scheme을 전달한다. Workspace의 pane 사전은 숨긴 헤더·배경도 갱신한다. NSColor를 CGColor로 복사한 포커스 선은 선택 appearance 안에서 다시 계산한다. 새 surface 생성/PTY 교체는 하지 않는다.
- 기존 Ghostty layer-hosting 초기화 순서를 유지한다. UI 색을 바꾸려고 TerminalView에서 wantsLayer를 먼저 켜지 않는다.
- `./scripts/check.sh` 성공: strict Swift format, 셸 문법, plist, release build, 코드 서명, 10개 테스트. 실제 PTY 테스트에서 숨긴 셸의 작업 완료, surface identity/셸 변수/레이아웃/포커스 유지, 반복 전환과 새 셸/복원 셸의 모드 상속을 확인했다. 분리된 UserDefaults suite에서 두 선택값의 재로딩과 잘못된 값 복구를 검사했다.
- 명시한 sRGB 값의 WCAG 상대 휘도 계산: 라이트 기본 텍스트 15.14:1, 보조 5.53:1, 선택 텍스트 11.30:1. 다크는 각각 16.28:1, 11.05:1, 8.28:1. 네이티브 컨트롤의 내부 색과 외부 프로그램이 지정하는 VT/RGB 색은 이 계산에 포함하지 않는다.

75개 공통 규칙의 기존 범위를 다시 검토했다. 변경된 색/표면/토큰/상태 일관성 규칙과 사용자 기본 배치 비교는 이 화면/코드/행동으로 재검사했다. 이전 PTY·저장·스크롤 검사는 이번 10개 테스트로 재실행했고, 변경하지 않은 구조/네이티브 예외의 이전 실기 기록은 보존했다.
마우스 휠 자동화, macOS 14 실기기, VoiceOver 전체 탐색, 임의의 모든 TUI 색·입력기는 여전히 검증 완료로 주장하지 않는다. 별도 시스템 자동 추종 모드는 이 요청의 두 수동 모드에 포함하지 않았다.
