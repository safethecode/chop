# 터미널 이름 변경 진입점

- 사용자 요구: 터미널6/5처럼 번호로 표시된 칸의 이름을 바꾸고, 아이콘 또는 자연스러운 호버 변화로 편집 가능함을 알 수 있어야 한다. D-NAME: 이름 오른쪽에 작은 SF pencil을 상시 표시하고 이름+연필 전체를 하나의 native 버튼으로 채택했다. 기존40pt 헤더·14pt medium 이름·보조 색상·12pt 행 간격을 사용한다. 추가 hover 애니메이션/색상 토큰은 만들지 않는다.
- 동작: 헤더 이름/연필 클릭과 헤더 우클릭,상단 탭 우클릭 `이름 바꾸기…`,기존⌘⇧R이 같은 native 편집 창으로 연결된다. 선택하지 않은 칸의 이름을 누르면 그 칸을 선택한 뒤 편집한다. 기존1–64자·앞뒤 공백 정리·제어 문자 거절·취소·자동 저장 경로를 재사용한다. 긴 전체 이름은 tooltip/AX에 남는다.
- F-RENAME-ICON-GAP: 최초 구현에서 이름 버튼이 남는 행 폭을 차지해 연필이 짧은 이름에서 멀리 떨어졌다. 버튼의 horizontal content hugging을 높여 짧은 이름 바로 옆으로 붙였다. 최종 실제 서버/빌드와 복원한6/5/7/8에서 확인했다.
- F-RENAME-TAB-REVEAL: 최소 파일 트리 창에서 마지막 탭을 긴 이름으로 바꾸면 기존 viewport 크기가 같아 선택 탭 오른쪽이 가려졌다. viewport뿐 아니라 탭 내용 폭 변화도 감지해 선택 탭을 다시 드러내도록 수정했다. 최초 회귀는 button.maxX469 > clip.maxX316.5로 실패했고 수정 후 통과했다. 최종 실제683pt 창/400pt canvas에서 선택한240pt 버튼 전체가 표시되고,전체 이름은 AX에 유지됨을 확인했다. 창 크기를 바꾸기 전에 이름을 저장한 결과를 직접 판독했다.
- 자동 검사: 최신main의 스크롤 PR25·중앙 배치 PR26과 결합해 전체26개 검사5.068초/check.sh/릴리스 번들 서명 통과. 두 scroller 스타일70회 경계와 빈 탭 본문 geometry,실제 PTY 통합 검사를 함께 실행했다. 로컬 .cache/test-rename-tab-before.log / .cache/check-name-controls-combined.log.
- 실제 클릭/대상: 첫 실행 셸6의 연필을 포인터로 직접 클릭해 native 창을 열고 서버로 바꿨다. 선택하지 않은 빈5의 이름 버튼은5를 편집했고 공백 입력을 거절했다. 빌드로 저장해도3개 빈 칸은 그대로였다. 빌드 선택 상태에서 선택하지 않은8을 우클릭해 긴 한글/이모지 이름으로 변경했으며 다른 칸은 그대로였다.
- 두 모드/최소/수명: 파일 트리를 켠 최소 격자에서 긴 이름이 말줄임되어도 연필/경로/확대/닫기 관계와40pt 헤더 정렬을 유지했다. 다크/라이트,확대·복귀,탭↔격자,기본1100pt와최소683pt/842pt 창을 실제 확인했다. 현재 scroller/중앙 배치 회귀도 확인했다. 서버 셸의 RENAME_FINAL=kept 실제 출력으로 기존 PTY가 유지됨을 확인했고 검증용 변수는 지웠다.
- 저장/복구: 앱 종료·재실행 후 서버/빌드/긴 이름과탭 모드·선택한 서버·한 실행 셸+세 빈 칸이 복원됐다. ⌘⇧R로 임시 이름을 입력하고Esc로 취소했을 때 서버 이름이 유지됐다. 최종 모든 이름은 기존6/5/7/8로 복원했다. 로컬 최종 .cache/chop-name-controls.jpg는 개인 파일 목록을 닫고 촬영한 편집하지 않은 실제 화면이다.
- 영향 판독: pane/PTY/경로/순서/중앙 추가/상단 아이콘/두 색상 표면/드래그/기존16칸 제한과 저장 형식은 유지된다. 변경 없는 조작의 이전 근거는 보존하고 변경된 헤더/탭·이름·취소·긴 이름·복원은 위 native 검증으로 추가 확인했다. 원형 중앙 버튼과 native keyboard focus의 기존 RUI-12 예외 CHOP-RUI-12를 보존한다.

- CI 후속 회귀 / F-RENAME-TAB-REVEAL: 최초 PR27의 runner에서 마지막 버튼maxX464가 clip.maxX457.5를 넘어 같은 검사가 실패했다. viewport/내용 폭 변경 감지만으로 충분하다는 이전 판독 범위를 수정한다. 스택의 fittingSize를 읽고 배치한 뒤 실제 arrangedSubviews의 trailing edge도 문서 폭에 포함하며,최종 폭을 저장한 뒤 선택 탭을 드러내도록 보완했다.
- 후속 검증: 라이트/다크×overlay/legacy×긴 한글·짧은 이름·64자W의12가지 이름 변경 조건을 같은 회귀에서 확인했다. 로컬 전체26개 검사5.471초/check.sh 통과. 최종 실제1배율683×432 창/400pt canvas에서64자W 저장 직후240pt 선택 버튼이x84..324에 완전히 들어갔고,라이트 전환 뒤에도 유지됐다. 이름은8로 복구하고1100pt 창/5번 선택/다크를 복원했다. 최종 변경 후 .cache/chop-fixed-plus.jpg도 새로 캡처해 중앙 위치를 다시 확인했다.
