# 클립보드 서비스 불가 시 초기화 충돌

2026-11-17, Codex 셀프 리뷰. 독립 승인 아님.

## 재현과 수정

C-0: 사용자가 게시 스크립트를 실행했지만 `./scripts/check.sh`가 프로젝트 구성 복원 검사에서
`Found a null pointer in a value of type NSPasteboard`와 signal6으로 종료됐다.
스크립트는 실패 시 종료하도록 되어 있어 Git push와 PR 생성에는 도달하지 않았다. 이 실행의 실패를
GitHub 인증 오류로 해석하지 않는다. 사용자가 별도로 제시한 GitHub CLI 계정/권한 확인은 정상이다.

엔진의 기본 인자 `.general`이 초기화 시 강제로 평가됐다. AppKit 헤더는 nonnull로 선언하지만 이
실행에서는 실제로 nil을 반환했다. 안전한 nullable Objective-C `perform` 반환값을 거쳐 조회하고,
조회 자체는 복사/붙여넣기 요청 때까지 미뤘다. nil 공급자의 읽기는 빈 값, 쓰기는 false를 반환한다.
파일 트리의 같은 직접 접근도 안전한 조회/실패 오류음으로 바꿨다.

C-1: 엔진 생성 중 공급자를 호출하지 않고, nil 공급자의 읽기/쓰기를 처리하는 회귀 검사가 통과했다.
실제 복사/붙여넣기 및 native 파일 URL 클립보드 검사의 assertion은 유지했다.

C-2: 수정 전에는 일반 클립보드 조회가 nil, 임시 클립보드 쓰기도 실패했다. 수정 후 전체 실행은
signal6 없이62개를 끝까지 수행했다.55개 통과/7개 실패/10개 issue,28.521초이며 전체 통과가 아니다.
실패는 프로젝트/실제 셸/종료/혼합 칸의 surface 생성, native 파일 URL 복사, WebKit 요청/대화상자다.
Ghostty 진단의 surface 초기화 반환은 `error.OutOfMemory`였다. 이를 물리 메모리 부족으로 단정하지 않는다.
같은 실행의 Metal 기본 장치 조회는 성공했다. root cause를 모두 클립보드 하나로 일반화하지 않는다.

## 실제 앱 확인

같은 release 바이너리를 `Chop 검증.app`으로 복사하고 검증용 `CFFIXED_USER_HOME`을 지정해 CUA로 열었다.
사용자의 기존 Chop(PID67582)은 유지했다. 새 UI나 문자열·색·레이아웃 토큰을 추가하지 않았다.

- C-3: 라이트 기본4칸에서 첫 터미널이 정상 생성됐다. 파일 트리의 한글/공백 파일을 우클릭해 경로를 복사하고 터미널에 붙여넣었다. 전체 경로가 입력됐으며 Enter로 실행하지 않고 지웠다.
- C-4: 셸에서 `CHOP_CLIPBOARD_OK`를 출력한 뒤 전체 선택/복사하고 파일 검색 입력에 붙여넣었다. 실제 출력과 표식이 들어와 터미널의 쓰기 콜백도 확인했다.
- C-5: 다크 모드 경로 복사/붙여넣기를 다시 실행해 같은 전체 파일 경로를 확인했다. 첫 시도에는 이전 선택 텍스트가 붙었고, Ctrl+C 뒤 다시 복사한 후 올바른 경로를 확인했다. CUA의 검색 입력 클릭 후 실제 first responder가 터미널로 남은 관찰도 있어 물리 클릭/초점의 전 조합을 통과했다고 주장하지 않는다. 복사/붙여넣기 내용과 도구의 초점 전달 범위는 구별한다.
- C-6: 실제 두 모드의 기존40pt 헤더·중앙 plus·48pt rail·파일 트리·28pt 인셋 입력을 현재 이미지로 대조했다. 원본 격자의 두 열/행 비율 약1과 이후 사용자 교정을 보존했다. UI 소스의 배치/타이포 변경은 없다.

CUA에서 직접 본 이미지/AX를 기록한 문서다. 별도 PNG나 물리 VoiceOver/고대비 검증으로 표현하지 않는다.

## 검사 진입 조건과 남은 작업

`scripts/check-system-services.swift`가 임시 이름 클립보드의 실제 쓰기/읽기를 확인하고 해제한다.
일반 클립보드를 덮어쓰지 않는다. `check.sh`가 빌드 전에 실행하며 실패하면 이유와 직접 연 macOS
터미널에서 재확인할 방법을 출력하고 nonzero로 종료한다. 원래 통합 검사를 생략하거나 성공 처리하지 않는다.

C-7: 현재 환경에서 갱신된 `check.sh`의 lint/문법/plist 검사 후 이 사전 확인이 명확한 한국어 메시지와
exit1로 종료하는 것을 확인했다. 정상 native 서비스가 제공되는 환경의 전체 검사와 PR·CI·머지는 남아 있다.
관련 코드/실제 앱 범위는 검증했지만 제품 통합 완료로 표시하지 않는다.
