# PR #13 입력 포커스 테두리 제거

2026-10-14, macOS26.5.2 / Apple Silicon, 구현자 셀프 리뷰. CUA의 실제 화면/AX·명령 실행과 코드/자동 테스트를 구분한다. PNG 내보내기나 독립적인 리뷰 승인으로 표시하지 않는다.

사용자는 포커스되어도 파란 border가 나오지 않기를 요청했다. 기존 pane 전체의1pt 포커스 경계를 제거하고 실제 입력 커서·first responder·선택한 칸 저장을 유지한다. 다른 색 테두리나 헤더 강조를 대신 추가하지 않는다. 네이티브 버튼·메뉴와 드래그 중 유효 대상2pt 경계는 입력 포커스와 별도 상태다.

| ID | 실제 재검증 |
|---|---|
| E-F1 | 수정 전 실행 앱에서 터미널11 전체를 감싸는 파란 테두리를 직접 확인했다. 사용자가 바꾼4칸(11·16 실행,15·14 빈 칸)을 유지해 새 빌드를 시작했다. 다크의 선택된11번에 테두리가 없고 실제 terminal AX 초점과 입력 커서가 있었다. |

| E-F3 | 라이트로 전환하고 `⌘⌥←`로11번을 선택했다. 같은 화면 내용과 커서가 유지되고 테두리가 없었다.11번 확대 상태에서도 테두리가 없었다. |

## 코드와 회귀 범위

TerminalPaneView의 isFocused 표현 상태와 Workspace의 해당 상태 배포만 제거했다. 실제 focusedID와 didFocus의 저장 알림, pane.focus의 first responder/Ghostty focus 전달, 공간 이웃 탐색과 키보드 라우팅은 유지한다. updateDropHighlight는 isDropTarget일 때만 borderWidth2, 나머지는0으로 설정한다. appearance 전환/편집 종료/드래그 종료에서도 입력 포커스 경계를 만들지 않는다. 레이아웃 치수·색 면·텍스트·메뉴/버튼 포커스 설정은 변경하지 않았다.

`./scripts/check.sh` 통과:11개 테스트3.641초, strict format / shell syntax / plist / release build / 코드 서명 검사 성공. 기존 실제 PTY focus·모드·칸 교환·확대·저장/복원 검사를 실행했다. 시각 테두리 제거는 실제 화면/행동으로 확인하며 구현 값을 그대로 반복하는 새 테스트는 추가하지 않았다. 로그는 로컬 `.cache/check-no-focus-border.log`다.

V-18은 사용자 요청에 따른 accepted-difference다. 이전 기본 canvas 기준에는 파란 경계가 있었으나 이번 명시 요청을 현재 기준으로 적용한다. 큰 터미널 영역·칸 구조·헤더/중앙 +·두 모드와 기존 행동은 보존한다. 입력 커서와 실제 AX 초점을 유지하며 네이티브 버튼·메뉴의 키보드 표시는 없애지 않는다. 터미널 pane 테두리를 요구하지 않는 범위를 RUI-23의 명시적인 사용자 예외로 기록한다. VoiceOver 전체 탐색과 모든 키보드/입력기·TUI/macOS14 실기기의 기존 미검증 범위를 확대하지 않는다.
