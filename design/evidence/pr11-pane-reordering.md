# PR #11 칸 이동과 모션 관찰

2026-10-14, macOS 26.5.2 / Apple Silicon, release Chop.app. 구현자의 셀프 리뷰다. CUA에서 직접 본 실제 화면/AX와 실행 기록을 구분하며, 독립적인 코드 리뷰 승인이나 PNG 내보내기로 표시하지 않는다.

## 사용자 교정과 재검증

사용자는 편집 중 터미널을 옮기기를 요청했고, 첫 구현의 작은 검은 아이콘 대신 창이 이동하는 모션을 요청했다. 이동 결과만 맞거나 손잡이 아이콘만 따라오는 것은 충분하지 않다. 수정한 빌드는 헤더와 실제 GPU 렌더를 포함하는 칸 전체를 native drag component로 제공하고, 원래 칸을 흐리게 표시하며 놓은 위치에서 새 자리로 이동한다.

| ID | 실제 실행 / 관찰 / 범위 |
|---|---|
| E-M1 | 사용 중인 비대칭 5칸(실행 3개/빈 칸 2개)을 보존했다. 편집 모드에서 각 헤더 앞에 네 방향 손잡이가 나타났고 AX 이름은 `터미널 11 이동`처럼 대상 이름을 포함했다. 약 295pt 폭의 작은 칸도 이름·경로·확대·닫기가 겹치지 않았다. |
| E-M2 | 터미널 11 좌상단 손잡이를 우하단 터미널 13 본문으로 드래그했다. 두 칸만 교환되고 다른 3칸·분할 위치는 유지됐다. 옮긴 터미널에서 `REORDER_STATE=preserved PID=88966`를 실제 출력했다. 이동 전 PID도 88966이었다. 화면/셸/변수를 재생성하지 않았다. |
| E-M3 | 옮긴 터미널에서 `⌘⌥⇧←`, 이어 `⌘⌥⇧→`를 눌렀다. 왼쪽 빈 칸과 교환한 뒤 제자리로 돌아왔고 동일 출력·입력 프롬프트·포커스가 유지됐다. |
| E-M4 | 우하단 손잡이를 toolbar로 드래그해 놓았다. 칸 순서는 변하지 않았고 흐림/대상 강조가 남지 않았다. 이어 원래 좌상단으로 드래그해 시험 전 순서로 복귀했다. |
| E-M5 | 다크에서 이동·키보드·취소를 실행했고 라이트로 바꿔 실제 5칸 헤더·손잡이·중앙 +·포커스 경계를 확인했다. header40/inset12/28pt 조작부와 본문 크기는 유지된다. 추가된 손잡이와 간격이 편집 중 제목 시작점을 40pt 이동시키는 의도적 차이다. |
| E-M6 | 자동화는 drag 시작~해제를 한 번에 수행하므로 미리보기의 중간 프레임이나 0.18초 곡선을 캡처하지 못했다. 이 부분을 정지 화면으로 검증했다고 주장하지 않는다. 최신 실행 빌드에서 사용자가 직접 확인한 뒤 `지금이 좋은 거 같아요`라고 답했다. 이는 요청한 모션에 대한 사용자 확인이며 독립 코드 리뷰가 아니다. |
| E-M7 | 사용자 추가 조작 후 실제 화면과 저장 파일 순서가 모두 11·16·15·14·13, 실행 칸 3개로 일치했다. 사용자가 바꾼 배치를 다시 덮어쓰거나 앱을 종료하지 않았다. 저장된 트리의 Codable roundtrip과 복원 유효성은 자동 테스트에서 검증했다. 이번 UI 실행에서 재시작까지 수행했다고 주장하지 않는다. |

## 코드·상태 검증

`LayoutNode.swapping`은 기존 UUID leaf만 교환하고 split UUID/축/비율을 유지한다. 같은 칸·없는 ID는 무동작이다. stable pane dictionary의 실제 NSView/TerminalView/Ghostty surface를 재배치하므로 셸을 닫거나 열지 않는다. 드롭은 편집 중 같은 작업 공간의 실제 source handle·일치하는 내부 pasteboard UUID만 허용하며 외부·다른 작업 공간·자기 자신·사라진 ID는 거절한다. native drag는 앱 내부 move만 제공한다.

미리보기는 전체 칸의 AppKit bitmap chrome과 Ghostty CALayer의 실제 IOSurface를 합친다. AppKit SDK의 NSDraggingImageComponent.contents는 CALayer가 허용하는 contents를 받는다. GPU view가 일반 bitmap cache에서 빠지는 경우에도 작은 아이콘이나 가짜 텍스트로 대체하지 않는다. 원래 칸 alpha 0.35, 유효 대상 border2(native focus color), 종료/취소 뒤 alpha1·강조 해제. 실제 크기나 세션 저장 형식은 바꾸지 않는다.

배치 모션은 현재 presentation 위치 → 최종 위치의 transform, 0.18초 easeInEaseOut이며 모델·저장은 즉시 반영한다. 빠른 후속 이동은 기존 presentation 위치를 출발점으로 사용한다. macOS 동작 줄이기 값에 따라 배치/취소 모션을 생략하는 분기를 코드로 확인했다. 시스템 설정 자체를 변경해 실기 실행하지 않았으며 동작 줄이기 환경의 체감 품질까지 검증했다고 주장하지 않는다.

`./scripts/check.sh` 성공: 11개 테스트 3.463초, Swift strict format / shell syntax / plist / release build / ad-hoc signature 검증 통과, 경고·오류 없음. 새 모델 테스트는 비대칭 트리의 geometry/minimum/역교환/무효 ID/직렬화를 확인한다. 실제 PTY 통합 테스트는 편집 밖 이동 거절, 전체 크기 preview와 GPU component 포함, 두 surface/NSView identity, 포커스, snapshot roundtrip, 키보드 좌우 이동과 원상 복귀를 검사한다. 기존 셸·테마·저장·숨긴 작업 테스트도 통과했다.

## 실패 기록과 경계

- V-15 / F-MOVE-01: 최초 손잡이 아이콘만 사용하는 drag preview는 사용자 기대에 미달했다. 이동 결과만 검증하고 직접 조작 피드백을 빠뜨린 것이 검토 누락이다. 전체 칸 preview·배치 모션으로 수정했고 E-M1–7, preview regression test, 사용자의 실제 확인으로 재검증했다. 최초 실패와 후속 수정 모두 보존한다.
- V-16: 첫 이동 손잡이에 존재하지 않는 SF Symbol을 강제 unwrap해 통합 테스트가 중단됐다. 실제 제공되는 네 방향 화살표로 바꾸고 optional 처리했다. 수정 뒤 11개 테스트와 실행 앱에서 정상 아이콘을 확인했다. 실패 로그는 로컬 `.cache/check-pane-reordering-symbol-failure.log`, 성공 로그는 `.cache/check-pane-motion.log`다.
- 글자·기본 canvas·모드 아이콘·중앙 +는 기존 계약을 유지한다. 새 손잡이는 편집 중에만 보이며 별도 탭/설명/로고/장식 애니메이션을 추가하지 않는다. 기본 4칸 진입은 기존 자료와 재실행된 통합 테스트로 확인하고, 사용 중인 5칸을 기본값으로 강제 초기화하지 않는다.
- VoiceOver 전체 탐색, macOS 14 실기기, 하드웨어 마우스 휠과 모든 입력기/TUI 조합의 기존 미검증 범위는 유지한다.

## 문구 계약

손잡이 tooltip은 `다른 칸으로 드래그해 자리 바꾸기`, AX는 `<칸 이름> 이동`이다. 메뉴는 `왼쪽/오른쪽/위/아래 칸과 자리 바꾸기`로 실제 교환 동작과 일치한다. 키보드는 편집 중 이웃이 있는 방향에서만 활성화한다. 기존 포커스 이동 `⌘⌥방향키`와 새 교환 `⌘⌥⇧방향키`를 구분했다. 상시 설명을 늘리지 않고 조작 옆 tooltip과 메뉴에 필요한 행동을 둔다. 한국어 용어·직접 행동·대상 명시·중복 여부를 검토했다.
