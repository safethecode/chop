# 세로 추가 영역 폭 교정

2026-10-20 Codex 셀프 리뷰. 외부 리뷰나 승인이 아니다. 비교 기준은 사용자의
“플러스 영역이 너무 넓어. 좁혀.” 요청과 직전 80pt 영역이다.

Q-WIDTH / V-51: 영역 80→48pt, native circular SF plus 56→32pt, 좌우 inset 8pt로
줄였다. 버튼은 regular 크기를 사용한다. 빈 터미널 칸 중앙의 56pt plus는 유지한다.
기존 배경·툴팁·접근성 이름·추가 순서·한도·키보드 동작은 바꾸지 않는다.
과거 80/56pt 관찰은 당시 결과로 보존하며 현재 치수는 이 기록과 DESIGN.md를 따른다.

실제 앱: 원래 실행 중인 Chop의 작업을 보존하기 위해 별도 bundle ID와
ChopWidthVerification/session.json을 사용하는 앱으로 확인했다. 소스 차이는 검증용
세션 경로뿐이다. 1100×752px 라이트 격자에서 줄어든 영역과 빈 칸의 큰 plus를
직접 비교하고, 세로 plus 클릭 후 터미널 2가 실행되는 것을 AX와 화면으로 확인했다.
다크 모드·파일 트리 숨김·탭 보기에서도 32pt plus가 오른쪽 중앙에 남았다.
native 모서리 드래그로 643×434px 창까지 줄여 버튼이 가려지지 않는 것을 판독했다.
스크린샷 px를 content pt와 등치하지 않는다. 내보낸 PNG가 아닌 CUA 직접 관찰 기록이다.

코드/동작: 기존 geometry 검사는 모든 preset·두 모드·파일 트리 개폐·최소 크기에서
32pt 버튼의 경계·중앙 정렬·hitTest를 확인했다. ./scripts/check.sh 전체36개 통과.
추가 순서와 PTY 보존은 변경하지 않았으며 기존 통합 검사도 통과했다.

사용자 교정으로 발견한 P2 밀도 문제는 fixed-and-verified, 변경 범위 aligned.
이번에 파일 드래그·전체 VoiceOver·고대비/Reduce Motion/macOS14 실기기를 새로
검증하지 않았다. 관련 없는 이전 규칙과 예외는 이전 근거를 유지한다.
