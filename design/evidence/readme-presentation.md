# README 소개와 macOS 스크린샷

- 범위: 사용자가 지정한 Documents/wratop/README.md의 중앙 로고·제목·짧은 소개·배지·목차·기능 표·실행·구조 구성을 참고했다. Chop의 실제 기능과 고정 의존성을 기준으로 내용을 새로 작성했다. 앱 소스·토큰·동작은 이 PR에서 바꾸지 않았다.
- 사진: CUA로 실행 중인 Chop의 macOS 창을 직접 촬영했다. 다크 격자, 라이트 격자, 라이트 상단 탭의 JPEG 3장, 각 2202×1506px다. 제목 막대·네이티브 컨트롤·터미널·파일 트리를 포함한다. 리터칭·모델 생성·가짜 터미널 출력은 사용하지 않았다.
- 공개 내용: 저장소의 실제 Sources/Resources/scripts/Package.swift 등을 `/tmp/chop-preview`에 복사한 뒤 실제 `ls -1`과 `head -n 24 Package.swift` 출력만 보였다. Downloads의 개인 파일 목록·사용자 홈 절대 경로·셸의 과거 출력은 사진에 넣지 않았다. 칸 이름은 촬영 당시 사용자의 이름을 그대로 보존했다.
- 촬영 검토: 격자로 돌아온 뒤 CUA의 첫 글자가 누락된 명령이 사진에 보이는 것을 로컬 이미지 판독에서 발견했다. 붙여넣기 후 실제 AX의 전체 명령과 성공 출력을 먼저 확인하여 두 격자 사진을 다시 촬영했다. 공개 브랜치에는 수정된 사진만 올렸다. 최종 세 이미지에서 본문을 가리는 포인터가 없고 창 가장자리의 미세한 포인터 표시만 남는다.
- 실제 앱은 촬영 후 홈 셸·다운로드 폴더·다크 격자·기존 창 크기·첫 칸 포커스로 복원했다. 기존 칸의 이름과 실행/빈 상태를 바꾸지 않았다.
- 문서 검토: 레이아웃별1/2/4개 제한을 현재 동작과 맞게 제거하고 전체16칸 상한·최소280×180pt·넘침 스크롤을 설명했다. 새 셸 복원, 개발용 서명/미공증, 후속 기능과 기존 macOS14/VoiceOver/마우스 휠의 실기 미검증 범위를 유지했다. 프로젝트 자체의 라이선스를 임의로 지정하지 않고 Ghostty 고지 링크를 보존했다.
- 링크/렌더: GitHub GFM 렌더 API가 picture/source를 보존함을 확인했다. HTML의25개 링크와9개 이미지 소스 중 로컬 경로 존재·목차 slug 일치·이미지 alt를 검사했다. 외부 링크의 모든 목적지 내용을 재조사한 검증은 아니다.
- GitHub 실물 판독: docs/open-source-readme 브랜치의 실제 GitHub 페이지에서 로고/5개 배지/목차/다크 격자 사진과 라이트 탭 사진이 깨짐 없이 보이는 것을 확인했다. 목차의 주요 기능·레이아웃·시작하기·단축키·기여하기를 각각 클릭해 해당 fragment 이동을 확인했다. 라이트 사진 원본도 로컬 이미지로 판독했다. GitHub의 전체 테마 설정을 변경하는 검증은 하지 않았다.
- 기본 검사: `./scripts/check.sh` 전체 통과,22개 테스트7.506초 통과. 로그는 로컬 `.cache/check-readme.log`다. 문서 변경 검증이며 기존 앱 전체 행동을 새로 검증했다는 의미는 아니다.
