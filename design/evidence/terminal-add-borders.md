# 세로 추가 영역 양옆 경계

2026-10-20 Codex 셀프 리뷰. 외부 리뷰나 승인이 아니다.
사용자 “border로 확실히 양 옆에 구분을 해야해” 요청에 따라 세로 추가 영역 안쪽의
왼쪽·오른쪽 끝에 전체 높이 1pt 경계를 추가했다. light B9BDC6 / dark555B67는 제품
선택값이다. 장식 선을 넣지 않던 이전 계약은 이 영역의 명시적 사용자 요청으로 바뀐다.
터미널 본문 포커스 테두리와는 별개이며, 본문 포커스 표시는 바꾸지 않는다.
48pt 영역·32pt native plus·좌우8pt는 보존한다. 파일 트리를 숨겨도 두 경계가 남고,
스크롤과 독립적으로 viewport에 고정된다. 경계는 내부에 그려 canvas나 패널 폭을 바꾸지 않는다.

E-BORDER-1: 별도 bundle ID/ChopWidthVerification 세션의 실제 AppKit 검증 앱에서
1100×752px 다크 탭·트리 숨김의 양옆 선을 직접 판독했다. 라이트 격자·트리 표시에서도
터미널 끝/추가 영역/파일 트리가 양옆 선으로 구분됐다. 중앙 작은 plus 클릭으로 터미널3이
실행되는 것을 AX로 확인했다. native 축소 후890×441px 격자에서도 전체 높이 두 선과
버튼 표시를 확인했다. 이미지 px와 content pt를 등치하지 않는다. CUA 직접 관찰 기록이며
내보낸 PNG가 아니다. 원래 실행 중인 Chop 작업은 종료하지 않았다.

E-BORDER-2: 셀프 리뷰에서 DESIGN.md의 rail 도입 전 최소 폭842pt가 남아 있어 현재
48pt를 포함한890pt로 바로잡았다. 최소 크기/두 모드/모든 preset의 기존 geometry·hitTest와
셸 통합 검사를 포함한 ./scripts/check.sh 전체36개를 통과했다.

V-52: 양옆 시각 구분이 부족하다는 사용자 교정 P2는 fixed-and-verified, 변경 범위 aligned.
관련 없는 파일 드래그·전체 VoiceOver·고대비/Reduce Motion·macOS14 실기기는 이번에
새로 검증하지 않았다. 이전 관찰과 현재 경계 추가를 구분한다.
