# 모든 터미널을 유지하는 단일 탭 보기

2026-10-15 KST / macOS26.5.2, 구현자 셀프 리뷰. 사용자 교정: 첫 번째 레이아웃은 터미널 수 때문에 막는 대신 하나를 크게 보여주고 상단에 모든 터미널 탭을 나열해야 한다. 기존 레이아웃 선택 crop의 위치/구조 아이콘/선택 강조는 유지하고 첫 항목의 동작만 이번 PR에서 바꾼다. 좌우/상하 제한 해제는 각각 별도 PR 범위다.

## 계약과 코드

단일 보기는 layout tree와 모든 pane/terminal/surface를 보존하는 presentation이다. optional snapshot.tabbed(true)만 저장하며 옛 v1 JSON은 필드 없이 decode한다. 기본 grid 진입은 유지하고 사용자가 저장한 tabbed 단일 빈 칸도 임의 grid로 바꾸지 않는다. 가로 탭40pt를 파일 헤더와 같은 줄에 배치하고 활성 pane의 중복 헤더40pt를 숨긴다. 태그/UUID로 선택하며 실제 active pane만 canvas에 붙이고 다른 셸은 살려 둔다. 기존14pt medium/중립 headerBackground/native 버튼 선택을 재사용한다. 탭 높이28/간격4/최대폭240/좌우8은 제품 선택값이다. 양끝 닫기/+는 기존28pt 아이콘이다. 긴 이름은 말줄임하고 full name/path tooltip/AX를 유지한다. 탭 목록만 overflow일 때 가로 스크롤한다.

선택/추가/닫기/rename/테마/키보드 focus와 재실행에 탭을 동기화한다. 닫기는 기존 작업 종료 확인을 호출하고 취소 시 유지한다. 비어지는 선택 탭을 제거하며 마지막 빈 칸은 유지한다. 새 탭은 선택 pane의 cwd를 이어 새 셸을 연다. 기존 전체16칸 저장/추가 경계는 이번1/2/4 preset 전환 문제와 별개인 기존 범위이며 이번 PR의 단일 보기 전환을 막지 않는다.

## 실제 화면과 행동

CUA clean 앱에서 사용자 기존4개의 실행 셸(11/16/5/6)을 모두 유지한 채 첫 아이콘을 눌렀다. 네 이름이 상단에 나란히 있고 활성 셸 하나가 전체 canvas에 보였다. 첫 탭에 검증용 셸 변수/출력을 넣고 다른 탭으로 갔다 돌아와 같은 값을 다시 출력했다. 새 +로 셸 하나를 추가하고 닫기 버튼으로 제거해 원래 네 탭이 유지됐다. 다른 새 검증 탭에 실제 한글/공백 긴 이름을 주고 full AX 이름과 말줄임을 확인했다.

초기 구현은1100×752에서681×432로 축소할 때 선택한 긴 탭이 목록 밖에 남았다. viewport 크기 변경 때 선택 항목을 reveal하도록 수정했다. 최종 clean 빌드에서 다시 새 긴 탭을 만들고 축소하니 선택한 탭의 파란 강조/말줄임/닫기/+가 화면 안에 보였다. Scroll Left AX 동작으로 처음 네 이름을 볼 수 있고, 선택 탭이 화면 밖이어도⌘W가 해당 검증 탭만 닫았다. 두 모드 최소/기본 창에서 글자/아이콘/terminal/file header 정렬과 콘텐츠 배경이 일관됐다.

단일 모드/첫 탭 선택 상태에서 앱을 종료하고 프로세스가 없음을 확인한 뒤 재실행했다. 단일 모드와 네 이름/첫 선택이 복원됐고 네 셸을 열었다. 셸 명령을 자동 재실행하지 않는다. 다시 grid를 누르면 같은 네 셸이 네 칸으로 돌아오고 개별 헤더가 복구됐다. 검증용 탭은 모두 닫고 사용자 기존 네 이름/Downloads/다크/1100×752로 복원했다.

이번 재실행 중 Downloads의 기존 native open 대기가 다시 관찰됐다. sample에서 백그라운드 FileManager.contentsOfDirectory→open 대기였고 UI와 터미널 입력은 정상 반응했다. 기존 폴더 선택기에서 Downloads를 다시 선택하니 실제100개 목록이 읽혔다. 별도 시스템 권한 창은 관찰되지 않았으며 원인을 TCC로 단정하지 않는다. 파일 로더 코드는 바꾸지 않았다. 이후 최종 재실행에서는 목록도 복원됐다.
