# PR #14 오른쪽 파일 트리

2026-10-14~15 KST, macOS26.5.2 / Apple Silicon, 구현자 셀프 리뷰. 실제 CUA 화면·AX·키보드/포인터 실행과 코드/테스트를 구분한다. PNG 내보내기나 독립적인 리뷰 승인으로 표시하지 않는다.

## 요구와 최종 구조

사용자는 오른쪽 파일 트리, 경로 직접 지정, 폴더 선택기, 다운로드·문서 같은 바로가기를 요청했다. 실행 화면을 본 뒤 검은 구분선이 이상하게 남는 문제와 파일 트리가 레이아웃 편집 툴바를 차지하는 구조를 교정했다. 최종판은 **공통 툴바 → 아래 터미널 canvas와 파일 트리**다. 파일 헤더와 첫 터미널 헤더가 같은 높이에서 시작하고 툴바는 전체 창 너비를 유지한다.

기존 사용자 canvas와 레이아웃/화면 모드 아이콘 참조는 그대로 사용한다. 새 파일 탐색은 현재 앱의 AppKit/SF Symbols와 사용자의 기능·계층 지시를 근거로 설계했다. cmux나 Finder 외형을 픽셀 복제했다고 주장하지 않는다. 폴더 선택기는 실제 NSOpenPanel이다. 터미널 목록용 왼쪽 탭 사이드바는 추가하지 않는다.

## 코드·자동 검사

FileTree는 한 단계 디렉터리 메타데이터만 읽고 폴더 우선 자연 정렬·숨김 제외·심볼릭 링크/패키지 leaf 처리를 한다. 경로는 `~`/절대/상대를 문자로 처리한다. 실제 I/O는 detached task에서 실행하고 UI 상태는 MainActor에서 갱신한다. 루트별 generation과 cancellation 검사가 이전 결과의 새 폴더 덮어쓰기를 막는다. 실패한 루트는 성공 경로 환경설정을 덮어쓰지 않는다. 하위 오류 행은 파일과 구분하고 새로고침으로 다시 읽는다.

NSOutlineView의 disclosure/선택·네이티브 키보드와 row 의미를 사용한다. 파일 행은 이름과 folder/doc 아이콘만 제공하고 선택된 항목의 Finder/복사 동작은 메뉴에 둔다. 빈 곳/오류 행의 우클릭은 오래된 파일을 대상으로 삼지 않게 선택을 해제한다. NSOpenPanel은 폴더 한 개만 선택하고 중복 sheet 생성을 막는다.

Workspace는 기존 toolbar 아래 bodyHost에 terminal canvas와 file split을 둔다. Split은 Workspace를 약하게 참조한다. 개폐는 기존 canvas/terminal을 재사용하고 폭과 minimum을 다시 계산한다. background drawing은 split bounds 안에 한정하고 숨긴 divider를 그리지 않는다. 본문 clip이 툴바를 덮는 overdraw를 막는다. 화면에 들어가지 않는 추가/패널 열기를 막고 사용자 선택 폭·표시 상태를 환경설정에 저장한다.

`./scripts/check.sh` 최종 성공:15개 테스트3.445초, strict Swift format / shell syntax / plist / release build / ad-hoc signature 검사 통과. 추가한4개 테스트는 one-level/natural sort/숨김/심볼릭 링크·문자 그대로의 경로, 실패/복구/성공 루트 복원, 늦은 결과 거절을 확인한다. 기존 실제 PTY flow에 패널 개폐의 동일 surface·layout·focus, 최소 폭/재열기 폭, 툴바 아래48pt 계층과 패널 우측 배치를 검증했다. 기존 모드/분할/교환/복원 검사도 통과했다. 로그는 로컬 `.cache/check-file-tree.log`다.

초기 폴더 복원 테스트는 같은 경로 URL의 directory flag 차이를 전체 URL 동등성으로 비교해 실패했다. 실제 경로 동등성으로 수정한 뒤 통과했다. 초기 로그는 `.cache/check-file-tree-url-identity-failure.log`에 보존한다. 제품 실패와 검사 조건 수정을 구분한다.

마지막 clean 재실행에서 Documents 아래 프로젝트 읽기가 장시간 `불러오는 중…`에 머물렀다. `sample`로 확인한 worker는 FileTree.entries → NSFileManager directory enumeration → OS `open`에서 대기했고 main thread는 정상 이벤트 루프였다. `/tmp` 직접 이동은 즉시 표시됐고 NSOpenPanel에서 프로젝트 폴더를 선택하자 실제 프로젝트 목록이 표시됐다. 권한 대기인지 다른 OS 원인인지는 확정하지 않았다. 이 조합에서 재실행만으로 항상 읽기가 끝난다고 주장하지 않으며, 다른 경로 이동과 폴더 선택기로 복구한 결과를 기록한다. 앱의 async generation/late-result 방어는 그대로 유지했다.

드래그 자동화는2× 스크린샷 좌표와 pt를 혼동한 첫 시도에서 이동하지 않았다. 최신 화면의 이미지 좌표50,200→1200,600으로 실행하자 실제 교환됐다. 임시 진단 로그는 제거했고 기존 drag 구현은 수정하지 않았다. 중간 프레임 캡처/모든 물리 입력 조합을 검증했다고 주장하지 않는다.

## 문구·시각 계약

파일 제목은 탐색 영역 이름이고 다른 설명을 반복하지 않는다. `홈/다운로드/문서`는 바로 이동하는 목적지 이름, `폴더 선택…`은 모달, `새로고침`은 현재 경로 재읽기, `Finder에서 보기/경로 복사`는 선택 항목의 실제 동작이다. `파일 트리 보기/숨기기`는 다음 전환 대상과 toggle/메뉴 상태가 일치한다. 읽기 실패는 확인된 사실과 가능한 복구만 안내하고 원인·시간을 추측하지 않는다. 한국어8원칙의 즉시 행동·핵심 정보·쉬운 말·중복·선택권을 대조했다. 기존 terminal14pt medium/header40/inset12/아이콘28, toolbar48을 사용하고 새 내부 gap8/행28/들여쓰기16/패널300(최소280)은 chosen macOS pt다. NSOpenPanel·표준 버튼/필드·행 선택은 native 예외다.

범위 밖: macOS14 실기기, 전체 VoiceOver 탐색, 모든 TUI/입력기, 하드웨어 휠의 기존 실기 미검증은 유지한다. 숨김 파일 전환·자동 폴더 감시·파일 편집/삭제·터미널 cwd 자동 동기화는 이번 요청 범위에 추가하지 않았다. 긴 목록의 native 스크롤은 유지하고 빈/소수 폴더에 별도 canvas 스크롤을 만들지 않는다.
