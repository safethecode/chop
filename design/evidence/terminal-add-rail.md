# 터미널 추가와 파일 검색 응답 개선

2026-10-20, Codex 셀프 리뷰. 외부 리뷰나 승인이 아니다. 비교 기준은 사용자 요청,
기존 DESIGN.md와 변경 전 실제 AppKit 창이다. CUA에서 직접 본 화면/AX와 실행 동작을
아래에 기록한다. 이 문서는 내보낸 PNG가 아니며 자동 게이트는 기록의 무결성만 검사한다.

## 변경 범위와 비교

Q-ADD: 기존 2×2 첫 셸·세 빈 칸과 중앙 56pt native circular plus를 유지하면서, 사용자가
요청한 canvas/파일 트리 사이의 세로 추가 영역을 도입했다. 폭 80pt는 제품 선택값이며
이미지에서 추정한 값이 아니다. 아이콘·버튼은 기존 SF plus/native circular를 재사용하고,
좌우 12pt와 fileListBackground를 사용한다. 글자/헤더/파일 목록 토큰은 바꾸지 않았다.
탭 사이드바·장식 선·별도 설명/제목을 추가하지 않았다. adapted-and-verified.

Q-GROW: 기존 5칸 격자의 위 3/아래 2 배치 대신, 최신 사용자 요청에 따라 두 열을 유지하고
아래로 늘어난다. 새 행 추가는 기존 분할 트리를 첫 자식으로 보존한다. 현재 작업 폴더를
새 행에 넘기고 첫 칸을 실행하며 옆 칸은 다음 추가를 기다린다. 사용자 요청에 따른
기존 배치 규칙의 변경이다. adapted-and-verified.

Q-SEARCH: 기존 28pt 검색창/14pt medium/상대 경로/목록 면과 빈 결과·오류 규칙을 유지한다.
입력 대기 75ms, 폴더 읽기 캐시 10초/10만 항목, 부분 결과 표시와 읽기 취소를 적용했다.
Sources에서 FileTree 3건 → FileTreeSearch 2건, 새로고침과 지우기, 라이트/다크를 실제로
실행했다. 200폴더·1만 파일 로컬 최적화 빌드는 첫 459ms → 다음 39ms였으며 환경별
속도 보장은 아니다. retained (표현), adapted-and-verified (응답 동작).

## 실제 앱 관찰

- E-ADD-1: 사용 중인 원래 Chop에 다른 작업 셸이 있음을 확인했다. 원래 앱을 종료하지
  않고 별도 bundle ID와 `ChopVerification/session.json`을 쓰는 검증 앱을 빌드했다.
  앱 소스 차이는 이 세션 경로뿐이며 제품의 번들 식별자는 생성한 검증 번들에서만 바꿨다.
- E-ADD-2: 세로 + 클릭으로 2번, 3번, ⌘T로 4번을 실행했다. 다음 +는 5번을 아래 새 행에
  열고 6번을 빈 칸으로 남겼다. 이어 6·7·8번을 열자 네 행이 되어 canvas만 세로로
  스크롤됐고 +는 viewport 중앙 오른쪽에 남았다. 다크 화면에서 두 열/헤더/목록 면과
  추가 영역의 중립 톤을 직접 판독했다.
- E-ADD-3: 1번 셸의 `CHOP_RAIL_CHECK=kept`를 설정하고 여덟 칸을 만든 뒤
  ⌘⌥위 세 번/왼쪽으로 1번에 복귀했다. 스크롤이 위로 이동했고 실제 명령 출력
  `RAIL=kept`를 확인했다. 단순 입력 에코로 셸 상태 보존을 판단하지 않았다.
- E-ADD-4: 라이트 모드, 파일 트리 숨김, 상단 탭 보기로 전환했다. 세로 +는 그대로였고
  클릭으로 9번 탭이 실행됐다. 16개까지 추가하자 세로 +와 탭 +가 disabled가 되고
  세로 +의 AX 도움말에 16개 한도를 표시했다. ⌘T가 추가하지 않는 것을 확인하고
  마지막 탭을 닫자 세로 +가 다시 활성화됐다.
- E-ADD-5: native 창 모서리를 드래그해 최소에 가까운 크기로 축소했다. CUA 이미지
  643×434px에서 빈 여백을 넘는 조작 없이 56pt +가 세로 영역 중앙에 남고 탭 목록만
  가로 탐색을 제공했다. 이미지 px를 content pt와 등치하지 않는다. 파일 트리를 다시
  열고 FileTree 3건 검색, 격자 전환/확대, 확대 중 +로 전체 배치 복귀와 새 칸 포커스를
  확인했다. 최소 격자에서 legacy 세로 손잡이가 폭을 차지하면 가로 탐색도 필요한
  기존 최소 크기 규칙은 유지한다. 넘침을 숨기지 않았다.
- E-ADD-6: 검증 앱을 종료했다가 다시 열어 16개 셸의 새 실행과 저장된 순서/선택/배치를
  확인했다. 기존 실행 프로세스를 복원한다고 주장하지 않는다.

## 코드·자동 검증과 셀프 리뷰

`./scripts/check.sh`: strict Swift 포맷/셸 문법/plist/release 빌드/앱 서명/아이콘과 전체
36개 테스트 통과. 기존 셸 통합 검사에 실제 16개 생성, 첫 빈 칸 순서, 최대 한도에서
불변, 닫힌 칸 재사용, 확대 종료, 탭 추가, cwd 상속, 첫 PTY 동일성/환경변수 출력과
snapshot 검증을 추가했다. 최소 창/모든 보기/두 모드/패널 개폐의 hitTest와 중앙 배치,
최소 문서 경계/스크롤바, 두 열 유지와 기존 분할 트리 보존도 검사한다.

V-50 (introduced, P2): 초기 시제품의 새 행 구조가 preset의 균형 트리와 달라 격자 선택
표시가 꺼졌다. 행들의 구조로 격자 여부를 판단하도록 고치고 실제 6·8칸에서 선택 표시를
다시 확인했다. fixed-and-verified.

새 +의 56pt 프레임/좌우 12pt/80pt 영역은 직접 코드로 확인했다. 세로 여백은 가용 높이에
따른 중앙 배치이며 고정 padding으로 환산하지 않는다. 기존 inset12/gap8/header40과
native SF 아이콘/버튼을 보존했다. 부모와 자식의 이중 여백·파일 트리 압축·추가 버튼 가림은
실제 기본/축소 창에서 관찰되지 않았다.

미변경 파일 URL 드래그·물리적 Reduce Motion/고대비 설정·전체 VoiceOver·macOS14 실기기는
이번에 새로 검증하지 않았다. 기존 문서 사진은 이전 버전의 예시로 유지했다. 관련 없는
기존 자산/테마/네이티브 예외는 이전 근거를 유지하며 새 검증으로 표시하지 않는다.
