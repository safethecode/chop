# 분할 기능 실제 앱 관찰

2026-10-14, macOS 26.5.2 / Apple Silicon. `build/release/Chop.app`을 CUA로 실행했다.
UI 구현 소스: `3811448`. 관찰 수단은 CUA의 AX 상태와 실제 스크린샷이다.
스크린샷은 작업 대화에 표시되었으며 이 파일은 이미지 원본이 아닌 관찰 기록이다.
기준은 사용자가 요청한 중앙 추가와 분할 작업, `DESIGN.md`다. cmux 외형의 픽셀 재현을 판정한 것은 아니다.

- 기본 콘텐츠 1100×720pt에서 `4` 선택: 네 칸이 작업 영역을 채우고, 각 빈 칸 중앙에 원형 `+` 하나씩 표시됐다. 사이드바가 없다.
- 네 칸 각각 실제 셸을 열었다. 셸 시작 메시지와 프롬프트가 각 칸 안에 렌더링됐다. 세 번째 셸부터 1/좌우/상하 프리셋이 비활성화됐다.
- 위쪽 두 칸 사이 경계를 x=550에서 x=680으로 드래그했다. AX divider 값이 680으로 바뀌고 각 터미널 출력이 새 폭에 맞춰 재배치됐다. 아래 두 칸의 경계는 유지됐다.
- 레이아웃 편집을 켰다. 네 실행 칸 중앙에 `터미널 추가`가 표시됐다. 첫 칸 중앙 버튼 → `아래에 추가`를 실행해 다섯 번째 칸과 새 셸이 생겼다. 편집을 끝내니 실행 칸의 중앙 버튼이 사라졌다.
- 첫 셸에서 미리 설정한 `CHOP_UI_SPLIT=alive`를 분할 후 읽었다. 출력은 `AFTER_SPLIT=alive`였다. 기존 프로세스 상태가 유지됐다.
- 첫 칸에서 `sleep 30` 실행 후 앱 종료: `취소`/`종료` 확인창이 나왔다. 취소 후 Ctrl+C로 작업을 중단하고 셸을 계속 사용할 수 있었다.
- 최종 글꼴 변경 후 다시 실행해 4칸 빈 화면을 관찰했다. 흰 작업 영역에서 이름·경로·프리셋을 읽을 수 있었고, 헤더 오른쪽 닫기는 빈 상태에서 비활성화됐다.

범위 한계: macOS 14 실기기, VoiceOver 전체 탐색은 이 관찰에 포함하지 않는다. 분할의 AX 값은 조회됐고 마우스 드래그는 실행했으나 보조 기술로 divider 조절하는 동작까지 확인한 것은 아니다.
